# 1. บทนำและขอบเขตของระบบ (Introduction & Scope)

← [[index|หน้าหลัก (Vault Home)]] · → [[02 - Overall Description]]

## 1.1 วัตถุประสงค์ (Purpose)

เอกสารฉบับนี้ระบุข้อกำหนดความต้องการของซอฟต์แวร์ (Software Requirements Specification - SRS) สำหรับ **MUSYA AI** ซึ่งเป็นแอปพลิเคชันบนเว็บ (Web Application) ที่ออกแบบมาเพื่อช่วยเหลือเจ้าหน้าที่สาธารณสุขและผู้ออกแบบนโยบายของ **เขตสุขภาพที่ 10** ในการแปลงคำถามด้านข้อมูลให้กลายเป็นเอกสารนโยบายสาธารณสุขที่มีหลักฐานอ้างอิงครบถ้วน 

เอกสารนี้ถูกจัดทำขึ้นโดยการถอดโครงสร้างพฤติกรรมการทำงานจากซอร์สโค้ดปัจจุบัน (As-built Source Code) และทำหน้าที่เป็นเส้นฐาน (Baseline) สำหรับการตรวจสอบยืนยัน (Verification), การทดสอบระบบ (Testing) และการต่อยอดพัฒนาระบบในอนาคต (ซึ่งเกี่ยวข้องกับ Phase-2 Backlog ที่ระบุไว้ในคลังเอกสารเสริม) 
โดยมีการขยายรายละเอียดเพื่อให้ผู้พัฒนาใหม่ หรือผู้มีส่วนได้ส่วนเสียในโครงการมีความเข้าใจอย่างแจ่มแจ้ง

## 1.2 ขอบเขตของผลิตภัณฑ์ (Product Scope)

ระบบ MUSYA AI **จะต้อง (shall) ทำสิ่งเหล่านี้ได้**:

- อนุญาตให้ผู้ใช้ที่ได้รับการยืนยันตัวตนแล้ว สามารถตั้งคำถามเกี่ยวกับข้อมูลสุขภาพด้วยภาษาธรรมชาติ (Natural Language) เป็นภาษาไทยได้ และต้องได้รับคำตอบกลับมาในรูปแบบสตรีมพร้อมการอ้างอิงที่เชื่อถือได้
- สามารถแยกแยะและส่งต่อคำถาม (Route) ไปยังโดเมนข้อมูล (Data Domain) และระบบดึงข้อมูล (Retrieval Pipeline) ที่ถูกต้องและเหมาะสมกับบริบทมากที่สุด (ได้แก่ หมวดอุบัติเหตุทางถนน, สุขภาพจิต, โรคไม่ติดต่อเรื้อรัง (NCDs), โภชนาการ, งานวิจัยทางการแพทย์, คลังความรู้องค์กร, และข้อมูลทั่วไปจากเว็บ)
- มีความสามารถในการรวบรวมข้อมูลที่ดึงมาได้ นำมาเรียบเรียงและจัดรูปแบบเป็นเอกสารทางนโยบายที่มีโครงสร้างชัดเจน ได้แก่ **สรุปนโยบาย (Policy Brief) / แผนยุทธศาสตร์ (Strategy Plan) / แผนการดำเนินงาน (Work Plan)** พร้อมสร้างรูปแบบการอ้างอิงบรรณานุกรมแบบ APA ให้อัตโนมัติ
- เก็บบันทึกประวัติการแชท (Chat Sessions) และเอกสารรายงานที่ผู้ใช้สร้างขึ้น โดยแยกตามผู้ใช้แต่ละคน (Per User) รวมถึงรองรับการส่งออกไฟล์เป็นรูปแบบ DOCX หรือ PDF เพื่อนำไปใช้งานต่อ
- มีระบบจัดการการเข้าถึงที่รัดกุม บังคับใช้การอนุมัติบัญชีและการจำกัดสิทธิ์ตามบทบาทของผู้ใช้ (Role-Based Access Control) แบ่งเป็น: ผู้ใช้ทั่วไป (`user`), ผู้ดูแลระบบ (`admin`), และผู้ดูแลระบบระดับสูง (`adminsuper`)

**ขอบเขตด้านภูมิศาสตร์:**
MUSYA AI ถูกออกแบบมาให้รับรู้และประมวลผลข้อมูล **เฉพาะภายใน 5 จังหวัดของเขตสุขภาพที่ 10** อย่างเคร่งครัด ได้แก่: อุบลราชธานี, ศรีสะเกษ, ยโสธร, อำนาจเจริญ, และมุกดาหาร หากมีคำถามที่ต้องการข้อมูลของจังหวัดที่อยู่นอกเขตพื้นที่นี้ ระบบจะถูกกำหนดให้ตอบปฏิเสธหรือแจ้งว่า "ไม่มีข้อมูล" อย่างชัดเจน และจะไม่มีการแทนที่ข้อมูลด้วยพื้นที่อื่นโดยพลการเด็ดขาด (อ้างอิงรายละเอียดใน [[03 - Functional Requirements|FR-CHAT-08]])

### สิ่งที่อยู่นอกเหนือขอบเขตในเวอร์ชันปัจจุบัน (Out of scope - Current release)

- ไม่รองรับการแสดงผลหน้าจอ (UI) เป็นภาษาอื่นๆ ที่ไม่ใช่ภาษาไทย (Non-Thai UI localisation)
- ความละเอียดของข้อมูลอุบัติเหตุระดับตำบล หรือ หมู่บ้าน ยังไม่เปิดใช้งาน (แม้ว่าโมเดลข้อมูลจะรองรับแล้ว แต่ในปัจจุบันยังไม่มีแหล่งข้อมูลดิบป้อนเข้าสู่ระบบ)
- ยังไม่มีการรับประกันความสามารถในการทำซ้ำผลลัพธ์แบบ Deterministic ที่แน่นอน 100% หรือมีระบบทดสอบอัตโนมัติ (Automated evaluation harness) สำหรับตัว AI (ประเด็นนี้ถูกติดตามอยู่ใน Phase-2 Epics E1/E13 ในคลังเอกสาร `musya-obsidian-document`)
- ข้อมูลอุบัติเหตุระดับบุคคล เช่น การสวมหมวกกันน็อก/เข็มขัดนิรภัย/อายุ/เพศ (ข้อมูลในตารางส่วนนี้ยังว่างเปล่า)

## 1.3 สรุปผู้ใช้งานระบบ (Actors Summary)

| ผู้ใช้งาน (Actor) | คำอธิบาย (Description) |
|---|---|
| **Guest (บุคคลทั่วไป)** | ผู้ที่ไม่ได้ลงชื่อเข้าใช้ระบบ สามารถเข้ามาหน้าแรกเพื่อทำการลงทะเบียน, เข้าสู่ระบบ, และขอรีเซ็ตรหัสผ่านได้ |
| **User (ผู้ใช้งานทั่วไป)** | บัญชีผู้ใช้งานที่ได้รับการอนุมัติแล้ว (`role=user`); มีสิทธิ์ในการแชท, สร้างรายงาน, จัดการไฟล์/อ้างอิง APA และบันทึกข้อมูลต่างๆ ในคลังส่วนตัวได้ครบถ้วน |
| **Admin (ผู้ดูแลระบบ)** | บัญชีระดับผู้ดูแล (`role=admin`); มีสิทธิ์เช่นเดียวกับผู้ใช้ทั่วไป และมีหน้าจอดูข้อมูลระบบเพิ่มเติม (Elevated views) |
| **Admin Super (ผู้ดูแลระดับสูง)** | บัญชีสิทธิ์สูงสุด (`role=adminsuper`); มีสิทธิ์เหนือสุดในการเข้าจัดการผู้ใช้ สามารถอนุมัติ/ปฏิเสธ/แก้ไขบัญชีผู้ใช้งานได้ผ่านหน้าระบบ (`/approved`) |
| **Backend (python-ai)** | ระบบประมวลผลเบื้องหลัง (Internal Service); ทำหน้าที่รัน AI pipelines และจะถูกเข้าถึงได้เฉพาะผ่านทาง BFF โดยใช้กุญแจ API `INTERNAL_API_KEY` เท่านั้น |
| **External APIs (บริการภายนอก)** | แหล่งข้อมูลภายนอกที่ระบบเรียกใช้ เช่น ThaiJo, PubMed (NCBI), Tavily (ค้นหาเว็บ), และ Open-Meteo (พยากรณ์อากาศ) ซึ่งจะถูกเรียกโดย Pipelines |

*รายละเอียดแบบเจาะลึกของผู้ใช้งานแต่ละประเภทและ Use-Case Diagram สามารถดูได้ที่ [[00 - Actors & Use-Case Map]]*

## 1.4 คำจำกัดความและคำย่อ (Definitions & Acronyms)

| คำศัพท์ / ตัวย่อ | ความหมาย |
|---|---|
| **BFF** | Backend-for-Frontend — ส่วนเซิร์ฟเวอร์เลเยอร์บนเทคโนโลยี Next.js ที่จัดการระบบล็อกอิน, ดูแลฐานข้อมูลของแอป (App DB) และเป็นตัวกลางส่งต่อคำขอ (Proxy) ไปยัง Python Backend |
| **SSE** | Server-Sent Events — โปรโตคอลการสื่อสารทางเดียว `text/event-stream` ที่ระบบใช้เพื่อสตรีมคำตอบที่กำลังประมวลผลแบบเรียลไทม์จาก Agent สู่ผู้ใช้งาน |
| **Domain (d0–d6/dt/obsidian)** | การจัดกลุ่มหมวดหมู่หัวข้อสุขภาพที่ระบบใช้เพื่อตัดสินใจเลือก Pipeline ในการตอบคำถาม (รายละเอียดอยู่ใน [[02 - Overall Description]]) |
| **Pipeline** | ลำดับการทำงาน (Workflow) แบบ Multi-agent ของ CrewAI ที่ถูกออกแบบมาเฉพาะสำหรับกลยุทธ์การค้นหาในแต่ละแบบ (เช่น แบบสืบค้นฐานข้อมูลอุบัติเหตุด้วย SQL, ค้นหาด้วย CSV, หาจาก ThaiJo ฯลฯ) |
| **Mode** | พารามิเตอร์ที่ฝั่ง Backend รับเข้ามาเพื่อระบุพฤติกรรมการทำงาน ได้แก่ `normal`, `stats`, `obsidian`, `tavily`, `thaijo`, `pubmed`, `research`, `report-gather`, `multi` |
| **Tool** | ปุ่มเครื่องมือที่ปรากฏหน้าแชทให้ผู้ใช้กดเพื่อเลือกพฤติกรรมเจาะจง ซึ่งจะถูกแมปเข้ากับ Mode ต่างๆ เช่น สร้างรายงาน→`report-gather`, สถิติ→`stats`, ค้นหาทั่วไป→`tavily`, วิจัย→`thaijo/pubmed/research`, คลังความรู้รายงาน→`obsidian` |
| **Zone 10 / เขตสุขภาพที่ 10** | พื้นที่เป้าหมาย 5 จังหวัดในภาคอีสานที่อยู่ภายใต้การดูแลของระบบนี้ |
| **Vault (Obsidian)** | ฐานข้อมูลความรู้แบบ Markdown (.md) ที่ผ่านการคัดกรองแล้ว ซึ่งระบบนำมาใช้เป็นฐานตั้งต้นให้กระบวนการ RAG ดึงข้อมูล และมีการนำไปดัชนี (Index) ไว้ใน PostgreSQL เพื่อความรวดเร็ว |
| **APA** | รูปแบบมาตรฐานการเขียนอ้างอิงบรรณานุกรม (APA Style) ที่ระบบนี้จะสร้างให้อัตโนมัติสำหรับเอกสารที่อัปโหลดและเอกสารอ้างอิงรายงาน |
| **พ.ศ. / ค.ศ.** | ปีพุทธศักราช (Buddhist Era) / ปีคริสต์ศักราช (Common Era) ระบบบันทึกในฐานข้อมูลเป็น ค.ศ. (ข้อมูลปี 2021–2026) โดยมีสูตรการคำนวณ พ.ศ. = ค.ศ. + 543 |
