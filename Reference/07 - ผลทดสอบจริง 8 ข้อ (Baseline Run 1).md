## ❌ ST-NCD-02 — ตัวเลขไม่ตรงกับไฟล์ไหนเลย

**ข่าวดี:** ค้นด้วย**ชื่ออำเภอ "คำชะอี" เจอ** ⇒ งานแปลงรหัสอำเภอเป็นชื่อในรอบก่อนได้ผล

**ข่าวร้าย:** AI ตอบ **61.56%** แต่ตรวจกับไฟล์จริงแล้วไม่ตรงสักไฟล์

| ไฟล์ | ค่าจริงของคำชะอี |
|---|---|
| `251144` (HDC, ปี 2562–) | **6.40%** (รายปี 5.49–7.60%) |
| `534175` (ปี 2565–2569) | 59.6 / 53.5 / 54.75 / 54.9 / 49.45 → เฉลี่ย ~54.4% |
| `486950` (เบาหวานที่มีความดัน — คนละตัวชี้วัด) | 44.38 / 42.54 / 47.74 |

AI อ้างช่วงปี **2562–2568** ซึ่งตรงกับไฟล์ `251144` เท่านั้น แต่ไฟล์นั้นให้ **6.40%**
ห่างจาก 61.56% เกือบ 10 เท่า

**ประเมิน:** เป็น factual claim ที่ **Incorrect** — และเป็นแบบที่อันตรายที่สุด
เพราะ 61.56% *ดูสมเหตุสมผล* สำหรับตัวชี้วัดนี้ ไม่มีอะไรสะดุดตาให้คนตรวจเอะใจ

> [!warning] มี 3 ไฟล์ที่เข้าข่ายคำถามเดียว
> `251144` · `534175` · `486950` เป็นคนละตัวชี้วัดกันแต่ชื่อใกล้กันมาก
> **AI ไม่ได้บอกว่าเลือกไฟล์ไหนและทำไม** ⇒ ตรวจสอบย้อนกลับไม่ได้
> นี่คืออาการของปัญหา `indicator_th` ซ้ำกันที่ยังเหลือ 52 ไฟล์

## 🔬 วิเคราะห์ลึก: รันคำถามเดียวกันซ้ำจากหน้าเว็บ ได้คนละคำตอบ

ผู้ใช้รันคำถาม `ST-NCD-02` ซ้ำจากหน้าเว็บ ได้ **95.27%** (รอบ API ได้ 61.56%)
**คำถามเดียวกัน ระบบเดียวกัน คนละคำตอบ** — ตามรอยแล้วพบต้นตอที่ชัดเจน

### 95.27% ไม่ใช่ตัวเลขที่แต่งขึ้น — แต่เป็น **คอลัมน์ผิด**

```
3004 ÷ 3153 = 95.27%   ← ที่ AI ตอบ
1667 ÷ 3153 = 52.87%   ← คำตอบที่ถูก
```

ทั้งสองตัวเลขอยู่ในไฟล์ `486950` แถวเดียวกัน (คำชะอี ปี 2567) จริง ๆ

| คอลัมน์ | ค่า | ความหมายจริง | `role` ในพจนานุกรม |
|---|---:|---|---|
| `B2 ทั้งหมด CHRONICFU` | 3,153 | ตัวหาร | denominator |
| **`ได้รับการตรวจวัดความดัน CHRONICFU`** | **3,004** | **ได้รับการ*ตรวจ*** | **measure** |
| `A2 ควบคุมได้ตามเกณฑ์` | 1,667 | **ควบคุมได้ดี** | numerator |
| `ร้อยละ A2/B2` | **52.87** | **คำตอบสำเร็จรูป** | percentage |

> [!danger] AI หยิบ "จำนวนที่ได้รับการตรวจ" มาใช้แทน "จำนวนที่ควบคุมได้ดี"
> แล้ว**ติดป้ายผิดในตารางของตัวเอง** — เขียนหัวคอลัมน์ว่า
> *"จำนวนผู้ป่วยเบาหวานควบคุมได้ดี (ราย) = 3,004"* ทั้งที่ 3,004 คือคนที่*ถูกตรวจ*
>
> ผลคือคำตอบ **95.27%** ซึ่ง**สูงจนน่าสงสัย** แต่ AI กลับชมว่า
> *"สูงกว่าเป้าหมายร้อยละ 60 อย่างมีนัยสำคัญ สะท้อนประสิทธิภาพการจัดการโรค"*
> — **ตีความผลลัพธ์ที่ผิดเป็นความสำเร็จ** ซึ่งอันตรายที่สุดเมื่อนำไปทำนโยบาย

### ที่แย่กว่านั้น — ตอบผิดตัวชี้วัดตั้งแต่แรก

ผู้ใช้ถาม **"ผู้ป่วย*ความดัน*ที่ควบคุมได้ดี"** แต่ AI ไปหยิบไฟล์
*"ร้อยละของผู้ป่วย**เบาหวาน**ที่มีความดันโลหิตควบคุมได้ตามเกณฑ์"* (`486950`)

**คนละประชากรกัน** — ไฟล์นี้นับเฉพาะผู้ป่วยเบาหวาน ไม่ใช่ผู้ป่วยความดันทั้งหมด
ไฟล์ที่ถูกคือ `534175` (คำชะอี 2567 = **54.75%**)

⇒ **มีความผิด 2 ชั้นซ้อนกัน: เลือกไฟล์ผิด แล้วเลือกคอลัมน์ผิดในไฟล์นั้นอีกที**

### ❌ ไม่ใช่ปัญหาจากบทสนทนาเก่า

สมมติฐานว่า "อาจดึง context จาก chat เก่ามาปน" **ตัดทิ้งได้จากหลักฐาน**:

| รอบ | history | คำตอบ |
|---|---|---|
| API (โน้ตนี้) | **`[]` ว่างเปล่าสนิท** | 61.56% |
| หน้าเว็บ | มีประวัติ | 95.27% |

**รอบที่ไม่มีประวัติเลยก็ยังตอบผิด** ⇒ ต้นเหตุอยู่ที่ **File Finder + Code Generator**
ไม่ใช่ Memory Agent · ประวัติแค่ทำให้ผิด*คนละแบบ* ไม่ได้ทำให้ผิด

### 🔑 ข้อสรุปสำคัญ: metadata มีคำตอบอยู่แล้ว แต่ไม่ถูกใช้

ตรวจ `csv_data_dict` ของ `486950` แล้วพบว่า**ระบบรู้ถูกหมดทุกอย่าง**:

- `indicator_th` = *"ร้อยละของผู้ป่วยเบาหวานที่มีความดันโลหิตควบคุมได้ตามเกณฑ์"* ✅
  (ถ้า AI อ่านบรรทัดนี้ ก็ควรรู้ว่าไม่ตรงคำถาม)
- `ได้รับการตรวจวัดความดัน` → `role = **measure**` ✅ (ไม่ใช่ numerator)
- `A1 ควบคุมได้ตามเกณฑ์` → `role = **numerator**` ✅
- `ร้อยละ A1/B1` → `role = **percentage**` ✅ **มีค่าร้อยละคำนวณไว้แล้วในไฟล์**

**AI เขียนโค้ดหารเองทั้งที่ไฟล์มีคอลัมน์ร้อยละสำเร็จรูปอยู่แล้ว**
และเลือกตัวตั้งจากคอลัมน์ที่พจนานุกรมระบุชัดว่าเป็น `measure` ไม่ใช่ `numerator`

> [!important] นี่เปลี่ยนการวินิจฉัยทั้งหมด
> เดิมสรุปว่า "AI แต่งตัวเลข" — **ไม่ใช่** · ตัวเลขจริงทุกตัว
> ปัญหาคือ **AI ไม่ได้ใช้ `role` ในพจนานุกรมที่เราเพิ่งสร้าง**
> ⇒ แก้ด้วยการปรับ prompt/pipeline ให้เคารพ `role` ได้ **ไม่ต้องแก้ข้อมูล**

### ทางแก้ที่เจาะจง เรียงตามผลตอบแทน

| # | แก้อะไร | ทำไมได้ผล | สถานะ |
|---|---|---|---|

## แก้ 4 เรื่อง

### 1. กฎการเลือกคอลัมน์ (`prompt_profile.py` + `data_dict_lookup.py`)

`describe_for_prompt()` เดิม**กรองคอลัมน์ `role=measure` ทิ้งตั้งแต่ต้น** ⇒ AI ไม่มีทางรู้
ว่ามีคอลัมน์นั้นอยู่และห้ามใช้ · ตอนนี้ลิสต์ชื่อออกมาพร้อมคำเตือน และบอกด้วยว่า
ไฟล์ไหนมีคอลัมน์ร้อยละคำนวณไว้ให้แล้ว

`CODE_GENERATOR_CORE_POLICY` เพิ่มกฎ 4 ข้อ (ข้อ 6–9) **พร้อมอ้างเคสจริง 95.27 vs 52.87**
— ตัวอย่างที่เคยผิดจริงสอนโมเดลได้ดีกว่าคำสั่งลอย ๆ

### 2. ประวัติแชทย่อขอบเขต (`question_resolver.py`)

> [!danger] เคสที่ผู้ใช้จับได้ — และผมเคยสรุปผิดว่า "ไม่เกี่ยวกับประวัติ"
> ประวัติคุยเรื่อง *"อำเภอคำชะอี จ.มุกดาหาร"* อยู่หลายเทิร์น
> คำถามใหม่: *"ปี 2569 **เขต 10** มีผู้ป่วยซึมเศร้าเข้าถึงบริการร้อยละเท่าไร"*
> ⇒ Memory Agent เติม "อำเภอคำชะอี จังหวัดมุกดาหาร" กลับเข้าไป **ตอบเฉพาะมุกดาหาร**
>
> จับยากมาก เพราะคำตอบดูสมบูรณ์ทุกอย่าง **แค่ครอบคลุมพื้นที่ผิด**
>
> รอบทดสอบ API ของผมใช้ `history=[]` จึงไม่เจอ — **ทำให้ผมสรุปผิดว่าประวัติไม่ใช่สาเหตุ**
> บทเรียน: ทดสอบด้วย history ว่าง **พิสูจน์ไม่ได้ว่าประวัติไม่มีปัญหา**

แก้ 2 ชั้น: เพิ่มกฎ "ขอบเขตที่คำถามใหม่ระบุเองต้องชนะของเดิม" ในพรอมต์ **และ**
เพิ่มการ์ด `_narrows_scope()` เชิงโค้ดที่ปัดผลทิ้งถ้าโมเดลยังย่อขอบเขตอยู่ดี
(ไม่พึ่งพรอมต์อย่างเดียว เพราะเป็นความผิดที่ผู้ใช้จับได้ยาก)

### 3. ไฟล์ HDC ซ้ำ (`036_superseded.sql` + `dedupe_hdc_imports.py`)

ตาราง HDC เดียวถูกนำเข้าซ้ำระหว่างพัฒนา — **26 ตาราง → 54 ไฟล์**
File Finder จึงเห็นหลายเวอร์ชันแล้วเลือกแบบสุ่ม คำถามเดิมได้คำตอบต่างกันทุกรอบ

### 4. 🔑 File Finder เห็น metadata ตอนเลือก (`catalog_for_finder()`)

**ช่องโหว่เชิงสถาปัตยกรรมที่อธิบายความผิดพลาดได้เกือบทุกเคส:**

```
File Finder    ── เห็นแค่ "ชื่อโฟลเดอร์"          ← ตัดสินใจเลือกไฟล์ตรงนี้
     ↓
Schema Analyst ── เพิ่งได้ metadata ตรงนี้
```

**metadata ถูกส่งให้ *หลังจาก* เลือกไฟล์ไปแล้ว** — ตัวที่ต้องตัดสินใจกลับไม่มีข้อมูลประกอบ

| ถาม | เคยหยิบไฟล์ | `indicator_th` ที่มีอยู่แล้วและจะช่วยได้ |
|---|---|---|
| ผู้ป่วย**ความดัน**ควบคุมได้ดี | ผู้ป่วย**เบาหวาน**ที่มีความดัน | บอกชัดว่าเป็นเบาหวาน |
| อัตรา**ฆ่าตัวตายสำเร็จ** | **ทำร้ายตนเองเข้าถึงบริการ** | คนละตัวชี้วัด |
| ผู้ป่วย**ซึมเศร้า**เข้าถึงบริการ | **SMI-V** | คนละตัวชี้วัด |

`catalog_for_finder()` ส่งสารบัญย่อเข้าพรอมต์ File Finder — **ตัวชี้วัด · ปี · จังหวัด ·
ระดับ · จำนวนคำเตือน** พร้อม `[ID:]` ให้อ้างย้อนกลับ (~100 รายการ/โดเมน ~11.7K ตัวอักษร)

```
[ID:186315] การคัดกรองความเครียด(ST-5)ในหญิงตั้งครรภ์ (ปี 2560-2569 · 5 จว. · ระดับหน่วยบริการ · ⚠️1)
```

พรอมต์เพิ่ม 2 ขั้น: **เทียบกับสารบัญเพื่อตัดไฟล์ที่ชื่อคล้ายแต่วัดคนละเรื่อง** และ
**ตัดไฟล์ที่ไม่ครอบคลุมปี/พื้นที่ที่ถาม**

## ยังไม่จบ

- **ยังไม่ได้ "อัตรา" ที่ถาม** — ได้แค่จำนวนดิบ เพราะต้อง join ไฟล์ประชากร
  ซึ่ง CSV pipeline ทำได้ทีละไฟล์
- **`result1`/`result2` ยังไม่รู้ว่าต่างกันอย่างไร** — อาการของ 52 ไฟล์ที่ไม่มีคำอธิบายคอลัมน์
- **บังคับอ้าง `file_id` จากโค้ด** (ข้อ 5) ยังไม่ทำ — ยังต้องพึ่ง LLM เขียนชื่อเอง

## ⚠️ ST-MH-10 — ไม่เดาตัวเลขที่ถาม แต่ยัดคำตอบอื่นมาแทน

บอกถูกว่าไม่มีข้อมูลรายได้ **แต่แล้วก็ไปคำนวณอย่างอื่นมาตอบ**:

> *"ได้คำนวณค่าเฉลี่ยจำนวนผู้ป่วยนอกจิตเวช ... มีค่าเฉลี่ยเท่ากับ **32.83 รายการต่อปี**"*

**32.83 ต่อปีทั้งเขตสุขภาพเป็นตัวเลขที่เป็นไปไม่ได้** — น่าจะเป็นค่าเฉลี่ยของแถวในไฟล์
ไม่ใช่จำนวนผู้ป่วย และผู้ใช้ไม่ได้ถามด้วย

ตามเกณฑ์แบบที่ 7 โดน 2 ทาง: **Relevance** หัก (section นอกเรื่อง) และ
**Factual Accuracy** หัก (claim ที่ตรวจแล้วผิด)

## 🟡 ST-NCD-05 — ได้คำเตือน Work Load แต่ไม่ได้คำเตือนรอยต่อ

เตือนเรื่อง Work Load ถูกต้อง ✅ แต่**ไม่ได้เตือนรอยต่อวิธีนับปี 2562→2563**

**สาเหตุ:** คำเตือนรอยต่ออยู่บนไฟล์ `298407` (`s_ckd_stage_hosp`) แต่ AI ไปหยิบ
ไฟล์อื่นที่มีตัวเลขหลักแสน (112,175 ครั้งในปี 2561) ซึ่งไม่มีคำเตือนนั้นติดอยู่

⇒ **ไม่ใช่ว่ากลไกพัง แต่ caveat ผูกกับไฟล์ ไม่ได้ผูกกับ "หัวข้อคำถาม"**
ถ้า AI เลือกไฟล์อื่น คำเตือนก็หายไปด้วย

## ⚠️ ST-NCD-09 — เลี่ยงคำถามเชิงนิยาม

ถามตรง ๆ ว่า *"นับเบาหวาน**และ**ความดัน หรือ**หรือ**"* แต่ AI **ตอบเป็นสถิติแทน**
(656,988 ราย · 76.26%) โดยใช้คำว่า "เบาหวานและ/หรือความดันโลหิตสูง" ลอย ๆ
**ไม่ได้อธิบายนิยามและไม่ได้อ้าง `definition` ที่ระบบมีอยู่**

⇒ `definition` / `numerator_th` / `denominator_th` เข้า `describe_for_prompt` แล้วจริง
แต่ **AI ไม่ได้ถูกสอนให้ใช้ตอบคำถามเชิงนิยาม** — ยังมองทุกคำถามเป็นคำถามตัวเลข

## ⚠️ ST-MH-06 — ไม่มีแถว "รวม" ปน แต่ตอบคนละเรื่อง

**ผลดี:** รายชื่ออำเภอที่ออกมาเป็นชื่ออำเภอจริงทั้งหมด **ไม่มีแถว "รวม" โผล่**

**ผลเสีย:** AI ยอมรับเองว่าใช้ *"ข้อมูลผู้ป่วยที่เข้าถึงบริการทั้งหมด ... ซึ่งใช้เป็น**ตัวแทน**
ในการประเมินการเข้าถึงบริการด้านสุขภาพจิต"* — **ไม่ใช่ข้อมูลผู้ป่วยซึมเศร้าที่ถาม**
และตัวเลข 160,313 สำหรับเมืองศรีสะเกษ คือผลรวมข้ามปี ไม่ใช่ค่าที่เทียบอันดับได้

การยอมรับว่าใช้ตัวแทนเป็นเรื่องดี (ซื่อสัตย์) แต่คำตอบยังไม่ตอบโจทย์
