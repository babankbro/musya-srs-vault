# 🔁 บั๊กตระกูล — เติมพื้นที่ที่ผู้ใช้ไม่ได้ถาม

← [[01 - Shared Agents (Memory & Router)]] · [[04 - Research Tool Agents]] · [[10 - Research Planner — ให้ Agent วางแผนค้นเอง]]

> **แก่นของปัญหา:** Memory Agent เติมชื่อจังหวัดจากประวัติแชทเข้าไปในคำถามที่ผู้ใช้
> **ไม่ได้ระบุพื้นที่เลย** แล้วชื่อจังหวัดนั้นไหลลงไปถึงเครื่องมือค้นทุกตัว
> **โผล่มา 3 ครั้งในเซสชันเดียว** ในรูปแบบต่างกัน จึงบันทึกเป็น "ตระกูล" ไม่ใช่บั๊กเดี่ยว

---

## ทำไมจับยาก

คำตอบที่ได้ **ดูสมบูรณ์ทุกอย่าง** — มีตาราง มีแหล่งอ้างอิง มีข้อเสนอแนะ
ผิดแค่ "ครอบคลุมพื้นที่ผิด" หรือ "หาเจอน้อยกว่าที่ควร" ซึ่งไม่มีอะไรฟ้อง
**ทั้ง 3 ครั้งผู้ใช้เป็นคนจับได้ ไม่ใช่เทสต์**

---

## ครั้งที่ 1 — ย่อขอบเขตที่ผู้ใช้ระบุไว้ชัด

```
ประวัติ : คุยเรื่อง "อำเภอคำชะอี จ.มุกดาหาร" หลายเทิร์น
ถาม    : "ปี 2569 เขต 10 มีผู้ป่วยซึมเศร้าเข้าถึงบริการร้อยละเท่าไร"
กลายเป็น: "...อำเภอคำชะอี จังหวัดมุกดาหาร..."  ⇒ ตอบแค่ 1 ใน 5 จังหวัด
```

**แก้:** การ์ด `_narrows_scope()` — ถ้าคำถามมีคำว่า "เขต 10 / ทั้งเขต / ทุกจังหวัด"
แล้วผลลัพธ์ดันเติมจังหวัดหรืออำเภอเข้ามา ให้ **ปัดผลของ Memory Agent ทิ้ง**

## ครั้งที่ 2 — เติมพื้นที่เข้าคำถามที่ไม่มีขอบเขตเลย (ThaiJo)

```
ถาม    : "มีงานวิจัยอะไรเรื่องการป้องกันการฆ่าตัวตายในชุมชนชนบท"
กลายเป็น: "...ในชุมชนชนบท ของจังหวัดยโสธรและจังหวัดศรีสะเกษ หรือไม่"
```

วัดกับ ThaiJo จริง:

| คำค้น | ผลลัพธ์ |
|---|---:|
| `ป้องกันการฆ่าตัวตาย ชุมชนชนบท ยโสธร ศรีสะเกษ` | **0 บทความ** |
| `ป้องกันการฆ่าตัวตาย ชุมชน` | **62 บทความ** |

> [!warning] การ์ดครั้งที่ 1 ครอบไม่ถึง
> `_narrows_scope()` ทำงานเฉพาะเมื่อผู้ใช้ **ระบุ "เขต 10" ไว้ชัด**
> เคสนี้ผู้ใช้ **ไม่ได้ระบุขอบเขตอะไรเลย** ⇒ ต้องเพิ่มการ์ดใหม่ ไม่ใช่แก้ของเดิม
> มีเทสต์ `test_การ์ดเดิมดักเคสนี้ไม่ได้_จึงต้องมีการ์ดใหม่` บันทึกเหตุผลไว้

**แก้ 3 ชั้น:**
1. `_adds_unasked_place()` — ปัดผล Memory Agent ทิ้งเมื่อคำถามเดิม **ไม่มีชื่อพื้นที่**
   และเป็น **คำถามหาความรู้** (งานวิจัย/มาตรการ/แนวทาง/รูปแบบ)
2. `_strip_places()` ที่ชั้น ThaiJo — ตัดชื่อจังหวัดที่ผู้ใช้ไม่ได้ถามออกจากคำค้น
3. กฎในพรอมต์ Keyword Extractor

**ขอบเขตแคบไว้ตั้งใจ** — คำถามตัวเลขอย่าง *"แล้วปี 2569 มีผู้ป่วยกี่คน"*
**ยังเติมจังหวัดจากบริบทได้เหมือนเดิม** เพราะกรณีนั้นการเติมถูกต้อง มีเทสต์ล็อกไว้

## ครั้งที่ 3 — เดียวกันแต่หนักกว่า (PubMed)

วรรณกรรมนานาชาติแทบไม่มีชื่อจังหวัดไทยปรากฏเลย:

| Query | ผลลัพธ์ |
|---|---:|
| `suicide prevention AND (Yasothon OR Sisaket)` | **1 บทความ** |
| `suicide prevention` | **10 บทความ** |

**แก้:** `_drop_unasked_provinces()` — ตัดทั้งกลุ่ม OR ที่มีแต่จังหวัดที่ไม่ได้ถาม
แต่ **เก็บ `Thailand` ไว้** ถ้าอยู่ในกลุ่มเดียวกัน (ยังช่วยหาได้ ต่างจากชื่อจังหวัด)
รองรับการสะกดหลายแบบ (`Si Sa Ket` / `Sisaket` / `Srisaket`)

> [!note] จงใจไม่แก้ `_strip_generic_geo_terms()`
> ฟังก์ชันนี้ตัด `Thailand` ทิ้งแล้วเก็บชื่อจังหวัดไว้ ตามหลักคิด "เฉพาะเจาะจงกว่าดีกว่า"
> ซึ่งในเคสนี้ทำให้ผลจาก 10 เหลือ 1 — **แต่สำหรับคำถามที่ผู้ใช้ถามจังหวัดนั้นจริง ๆ
> การเอาบทความท้องถิ่นขึ้นก่อนแล้วค่อยเติมด้วย query กว้าง (pass 2) เป็นพฤติกรรมที่ถูกต้อง**
> ปัญหาไม่ได้อยู่ที่ฟังก์ชันนี้ แต่อยู่ที่จังหวัดที่ไม่ได้ถามถูกใส่มาตั้งแต่ต้นทาง
> มีเทสต์ล็อกไว้ว่าพฤติกรรมเดิมไม่เปลี่ยน

## บทเรียน

| บทเรียน | ที่มา |
|---|---|
| **ทดสอบด้วย `history=[]` พิสูจน์ไม่ได้ว่าประวัติไม่มีปัญหา** | รอบทดสอบ API ของผมใช้ history ว่าง จึงไม่เจอ และ **สรุปผิดว่าประวัติไม่ใช่สาเหตุ** |
| **กันด้วยโค้ด ไม่พึ่งพรอมต์อย่างเดียว** | เป็นความผิดที่ผู้ใช้จับได้ยาก ปล่อยให้พลาดไม่ได้ |
| **กันหลายชั้น** | จังหวัดถูกเติมได้หลายจุดในสายท่อ (Memory → Keyword Extractor → คำค้นจริง) |
| **การ์ดที่แคบเกินไปครอบไม่ถึงญาติของบั๊กเดิม** | การ์ดครั้งที่ 1 ดักครั้งที่ 2 ไม่ได้เลย |
| **ตั้งขอบเขตการ์ดให้แคบ แล้วล็อกด้วยเทสต์** | ห้ามพังเคสที่การเติมพื้นที่ถูกต้องอยู่แล้ว |

## ยังไม่จบ

- **Tavily และคลังรายงานยังไม่ได้ตรวจ** ว่ามีอาการเดียวกันหรือไม่
- การ์ดใช้ **รายการคำ** ตัดสินว่าเป็น "คำถามหาความรู้" — คำที่ไม่อยู่ในรายการจะหลุด
