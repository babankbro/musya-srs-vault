# 📐 บั๊กตระกูล — การนำเสนอผลลัพธ์

← [[02 - Frontend Design]] §5.5 · [[02 - Prompt Strategy & Anti-Hallucination]] · [[04 - Research Tool Agents]] · [[11 - บั๊กตระกูล เติมพื้นที่ที่ผู้ใช้ไม่ได้ถาม]]

> **แก่นของปัญหา:** ระบบ **หาคำตอบถูก** แต่ **นำเสนอผิด** — ตัวเลขถูก คำนวณถูก ค้นเจอจริง
> แต่สิ่งที่ปรากฏบนหน้าจอทำให้ผู้อ่านตีความผิด อ่านไม่ออก หรือเห็นของที่ไม่เกี่ยวปนมา
>
> รวม 4 อาการที่ **ผู้ใช้จับได้เองทั้งหมด** ในเซสชันเดียว (2026-08-06) จึงบันทึกเป็น "ตระกูล"
> เพราะมีรากร่วมกันคือ **"เชื่อว่าพรอมต์สั่งแล้วจะได้ตามนั้น"** และ **"ไม่มีชั้นตรวจตอนแสดงผล"**

## ทำไมจับยาก

เหมือนกับ [[11 - บั๊กตระกูล เติมพื้นที่ที่ผู้ใช้ไม่ได้ถาม|ตระกูลก่อนหน้า]] — คำตอบ **ดูสมบูรณ์ทุกอย่าง**
มีตาราง มีสูตร มีบทวิเคราะห์ มีอ้างอิง ไม่มีอะไร error ไม่มีอะไรฟ้อง
เทสต์ backend ก็ผ่านหมด เพราะทุกอาการเกิด **หลังจาก** ตัวเลขถูกคำนวณเสร็จแล้ว

## อาการที่ 1 — จำนวนคนมีทศนิยม

```
ถาม  : "ปี 2569 เขต 10 มีผู้ป่วยเบาหวานขึ้นทะเบียนกี่คน แยกรายจังหวัด"
ได้   : | อุบลราชธานี | 189,542.00 |
ควรได้: | อุบลราชธานี | 189,542    |
```

**รากของปัญหา:** กฎในพรอมต์เขียนว่า *"ตัวเลขทศนิยมแสดง 2 ตำแหน่ง"* ลอย ๆ **ไม่แยกชนิดตัวเลข**
และท่อ CSV สั่งตรง ๆ ว่า `df_display = df_display.round(2)` — ปัด **ทั้ง DataFrame** รวมคอลัมน์นับหัวคน

**ทำไมมันสำคัญกว่าที่คิด:** `.00` ทำให้รายงานราชการดูเหมือนตัวเลขนั้นผ่านการหาร/ประมาณมา
ทั้งที่เป็นการนับหัวจริง ผู้บริหารที่อ่านอาจตั้งคำถามผิดจุด

**แก้ 2 ชั้น** (ชั้นเดียวไม่พอ เพราะพรอมต์คือ "ขอความร่วมมือ" ไม่ใช่การบังคับ):
1. **ต้นทาง** — `prompt_profile.NUMBER_FORMAT_POLICY` + กฎปัดเลขแยกชนิดคอลัมน์ใน
   `csv_pipeline` / `multi_csv_pipeline` (`round(0).astype("Int64")` สำหรับตัวนับ)
2. **ปลายทาง** — `chartAdvisor.formatCell()` ตัด `.00` ตอนแสดงผล
   ⚠️ **แตะเฉพาะคอลัมน์ที่หัวตารางบอกว่าเป็นตัวนับ** — ปัด `52.87%` เป็น `53%` คือทำข้อมูลเสียหาย ไม่ใช่จัดรูป

## อาการที่ 2 — สูตร LaTeX แสดงเป็นโค้ดดิบ

```
ได้   : $$ \text{ร้อยละ} = \left( \frac{2036}{6563} \right) \times 100 $$
ควรได้: สมการที่มีเศษส่วนซ้อนชั้นจริง อ่านออกได้
```

**รากของปัญหา:** `INSIGHT_RESPONSE_BLUEPRINT` **สั่งให้ agent เขียนสูตร LaTeX มาตั้งแต่ต้น**
แต่ `MarkdownContent.tsx` เป็น markdown parser ที่เขียนเอง **ไม่มีตัวเรนเดอร์คณิตศาสตร์**
— ฝั่งหนึ่งผลิตของที่อีกฝั่งอ่านไม่เป็น เป็นช่องว่างที่ไม่มีใครสังเกตจนผู้ใช้เห็นเอง

**แก้:** `MathContent.tsx` — parser + renderer ของ LaTeX subset ที่ agent ใช้จริง
(`\frac \text \left\right ^ _ \hat \sqrt \times` ฯลฯ) รองรับ `$$…$$` (บรรทัดเดียว/หลายบรรทัด),
`$…$` และ `\(…\)` · **พาร์สไม่ได้ให้ถอยไปแสดงต้นฉบับ** ห้ามทำจอขาว

> [!note] ทำไมไม่ใช้ KaTeX
> โปรเจกต์นี้ไม่มี markdown/math dependency เลยสักตัว และ build จริงรันใน Docker
> การเพิ่ม dependency ที่ verify ไม่ได้ในเครื่องเสี่ยงกว่าประโยชน์ · subset ที่ agent ผลิตจริงแคบมาก

## อาการที่ 3 — กราฟผิดชนิด และหายไปครึ่งตาราง

```
ตาราง: | ระยะ CKD | 2561 | 2562 | ... | 2568 |   (Stage 3/4/5)
ได้   : กราฟแท่ง เส้นเดียว (Stage 3) — Stage 4/5 หายเงียบ ไม่มีอะไรฟ้อง
ควรได้: กราฟเส้น 3 เส้น แยกตาม stage ไล่ตามปี
```

**รากของปัญหา 2 ข้อ:**
1. โค้ดเดิมหา *คอลัมน์ตัวเลขคอลัมน์แรก* แล้ววาดคอลัมน์นั้นคอลัมน์เดียว — ที่เหลือถูกทิ้งโดยไม่แจ้ง
2. มีปุ่มแค่ `ตาราง / แท่ง / วงกลม` **เหมือนกันทุกตาราง** และ **ไม่มีกราฟเส้นเลย**
   ทั้งที่ข้อมูลอนุกรมเวลาต้องใช้กราฟเส้น ผู้ใช้ต้องเดาเองว่าอันไหนเหมาะ

**แก้:** `chartAdvisor.ts` (ตรรกะล้วน) + `TableCharts.tsx` (SVG 4 ชนิด รองรับหลายชุดข้อมูล)
พร้อม **ป้ายอันดับ 1-2-3 และเหตุผล** บนปุ่ม — ยังกดเลือกเองได้ทุกปุ่ม ไม่บังคับ

**เกณฑ์จัดอันดับ** (ดูรายละเอียดที่ [[02 - Frontend Design]] §5.5):

| รูปทรงข้อมูล | อันดับ 1 | เหตุผล |
|---|---|---|
| แกน X เป็นมิติเวลา | **เส้น** | สายตาอ่าน "ทิศทาง" ได้ตรง · วงกลมตกอันดับ (แสดงสัดส่วน ณ จุดเดียว) |
| เทียบข้ามหมวด ชื่อสั้น | **แท่งแนวตั้ง** | เทียบความสูงได้ทันที |
| เทียบข้ามหมวด ชื่อยาว/>12 รายการ | **แท่งแนวนอน** | ป้ายกำกับไม่ถูกตัด |
| ชุดเดียว ค่าบวก 2–7 รายการ | วงกลม ขึ้นอันดับ 2 | เห็นส่วนแบ่งเทียบยอดรวม |

**กับดักที่เจอระหว่างแก้:** ตารางที่มีทั้ง `จำนวนคน (189,542)` และ `ร้อยละ (5.12)`
ถ้าวาดรวมแกนเดียว แท่งร้อยละจะเตี้ยจนมองไม่เห็น ⇒ `buildChartData()` เลือกเฉพาะกลุ่มคอลัมน์
ที่มีมากกว่า เสมอกันให้ **ตัวนับ** ชนะ (เป็นปริมาณหลัก)

## อาการที่ 4 — งานวิจัยคนละเรื่องปนมา

```
ถาม  : "มีหลักฐานเชิงประจักษ์อะไรบ้างว่ามาตรการลดหวานมันเค็มระดับชุมชนได้ผล"
ได้   : ... + "การศึกษาการรุกล้ำความเค็มและมาตรการควบคุมความเค็มในแม่น้ำท่าจีน"
```

ตรงกันแค่ตัวอักษร **"เค็ม" + "มาตรการ"** แต่เป็น *ความเค็มของน้ำทะเลหนุน* (อุทกวิทยา/สิ่งแวดล้อม)
ไม่ใช่ *ความเค็มของอาหาร* (โภชนาการ/สาธารณสุข)

**รากของปัญหา:** ThaiJo/PubMed จับคู่ด้วย **คำ** ไม่ใช่ **ความหมาย**
ที่ผ่านมาแก้ที่ *คำค้น* มาหลายชั้นแล้ว (`_strip_places`, `strict=true`, progressive AND)
แต่คำพ้องบริบทไม่มีทางแก้ที่คำค้นได้ — **ต้องมีด่านอ่านความหมายหลังได้ผลลัพธ์**

**แก้:** `research_relevance.py` — step SSE ใหม่ `relevance` ใช้ร่วม ThaiJo + PubMed
ดูสเปคเต็มที่ [[04 - Research Tool Agents]] A0.5

**สิ่งที่ต้องระวังที่สุดคือการ์ดตัวนี้เอง** — ตัวกรองที่ตัดเกินอันตรายกว่าไม่มีตัวกรอง
เพราะผู้ใช้ไม่มีทางรู้ว่าอะไรหายไป จึงบังคับ: เอนไปทางเก็บไว้ · คำตอบตีความไม่ได้ = เก็บ ·
ตัดหมดเกลี้ยง = ถามซ้ำแล้วเชื่อผลที่ตัดน้อยกว่า · **แสดงรายการที่ตัดพร้อมเหตุผลให้ผู้ใช้เห็นเสมอ**

## บทเรียนร่วมของทั้งตระกูล

1. **พรอมต์ไม่ใช่การบังคับ** — ทุกกฎที่ "สำคัญพอที่ผิดแล้วผู้ใช้เห็น" ต้องมีชั้นบังคับด้วยโค้ดด้วย
   (แพทเทิร์นเดียวกับ `_linkify_bare_urls` และ relevance gate รายไฟล์)
2. **ระวังกฎเดียวใช้กับทุกอย่าง** — `round(2)` ทั้ง DataFrame · ปุ่มกราฟชุดเดียวทุกตาราง
   ล้วนเกิดจากการไม่แยกแยะชนิดของสิ่งที่กำลังจัดการ
3. **การตัดข้อมูลทิ้งเงียบ ๆ คือบั๊กที่ debug ไม่ได้** — ทั้งคอลัมน์ที่กราฟไม่วาด
   และบทความที่ตัวกรองตัด ต้องบอกผู้ใช้เสมอ
4. **ผู้ใช้จับได้ก่อนเทสต์อีกครั้ง** — ฝั่ง frontend ยังไม่มีเทสต์อัตโนมัติเลยแม้แต่ตัวเดียว
   (ดู [[03 - Traceability Matrix]] ส่วนที่ 6 ข้อ 1) ตระกูลนี้เป็นหลักฐานเพิ่มว่าช่องโหว่นั้นมีราคาจริง
