## 🔴 E1 — Determinism (ลำดับ 1 ตาม backlog)

### ที่ backlog ขอ
`temperature=0` + `top_p=1` + `seed` คงที่ · pin เวอร์ชันโมเดล · deterministic retrieval ·
response cache · corpus versioning

### ของจริงในโค้ด

| ข้อ | สถานะ | หลักฐาน |
|---|:---:|---|
| `temperature=0` | 🔴 | ค่าที่ใช้จริงกระจาย **0.0–0.3** — `obsidian_fullcontext.py:227` = 0.1 · `csv_pipeline.py:612` = 0.3 · `accident_policy_orchestrator.py:38` = 0.3 |
| `top_p` / `seed` | 🔴 | **ไม่มีสักจุดเดียวในทั้ง repo** |
| pin โมเดล | ✅ | `llm_provider.py` ระบุรุ่นตายตัวทั้ง 3 ค่าย ไม่ใช้ alias `latest` |
| deterministic retrieval | 🔴 | ไม่มีการล็อกลำดับผลค้น |
| response cache | 🔴 | Redis ใช้เก็บประวัติแชทกับแคช PDF ของ ThaiJO เท่านั้น ไม่มี cache คำตอบ |
| corpus versioning | 🔴 | ไม่มี |

> [!danger] อุปสรรคจริงที่ backlog ยังไม่รู้ — LLM ถูกสร้าง 13 จุดกระจาย
> มีจุดที่สร้าง `LLM(...)` ตรง ๆ **13 จุด** แต่ผ่านศูนย์กลาง `build_chat_llm()`
> แค่ **4 จุด** อีก 7 ไฟล์สร้างเองล้วน ๆ:
> `accident_chat_orchestrator` · `accident_policy_orchestrator` · `error_monitor_agent` ·
> `obsidian_agent` · `router` · `tavily_pipeline` · `thaijo_agent`
>
> ⇒ **ตั้ง `temperature=0` ที่เดียวแล้วจบไม่ได้** ต้องรวมทางเข้าก่อน
> ไม่งั้นแก้ 4 จุด เหลืออีก 9 จุดที่ยังสุ่มอยู่ แล้วจะสรุปว่า "แก้แล้วยังไม่นิ่ง"

### แผนที่เสนอ

**ขั้น 1 — รวมทางเข้าให้เหลือประตูเดียว** (งานหลัก ประเมิน 1–2 วัน)
ขยาย `build_chat_llm()` ให้รับ use-case แทน temperature ดิบ แล้วย้าย 13 จุดมาเรียกผ่านมัน
เขียนเทสต์ที่ **ไล่สแกนทั้ง `src/agents/` แล้ว fail ถ้าเจอ `LLM(` นอก `llm_provider.py`**
— ด่านนี้สำคัญกว่าการแก้ค่า เพราะกันไม่ให้จุดที่ 14 โผล่มาในอีก 3 เดือน

**ขั้น 2 — ตั้งค่าให้นิ่ง** (ครึ่งวัน)
`temperature=0` · `top_p=1` · `seed` คงที่ ที่ประตูเดียวนั้น

> [!warning] `seed` ไม่ได้แปลว่าผลเหมือนเดิม 100%
> Gemini กับ OpenAI ให้ `seed` เป็น **best-effort** ไม่ใช่การรับประกัน
> ผู้ให้บริการเปลี่ยน backend เมื่อไหร่ผลก็เปลี่ยนได้ ⇒ เกณฑ์ "diff = 0"
> ที่ backlog ตั้งไว้จะผ่านได้จริงก็ต่อเมื่อมี **cache** (ขั้น 3) มาปิดท้าย
> ถ้าไม่ทำขั้น 3 ให้แก้เกณฑ์เป็น "ตัวเลขในคำตอบตรงกัน 100% ส่วนถ้อยคำต่างได้"

**ขั้น 3 — cache คำตอบ** (1 วัน)
key = `hash(prompt + provider + model + corpus_version)` เก็บใน Redis ที่มีอยู่แล้ว
`corpus_version` เอามาจาก `max(built_at)` ของ `csv_data_dict` + `max(indexed_at)` ของ
`obsidian_notes` — ไม่ต้องสร้างระบบ versioning ใหม่ ใช้ของที่มีอยู่

**ผลที่ได้:** ปลดล็อกการวัดของฟอร์ม 3, 5, 7, 9 ตามที่ backlog ระบุ + ลดค่า API จากคำถามซ้ำ

## 🟡 E2 — Retrieval ตรงปี + Citation

### ของจริงในโค้ด

**ปี — มีข้อมูลแต่ยังไม่ได้ใช้เป็นตัวกรอง**
`csv_data_dict` เก็บ `year_min` / `year_max` / `years` ครบทุกไฟล์ และ `describe_for_prompt()`
ส่งเข้า prompt ว่า `ขอบเขตข้อมูลจริง: ปี 2559–2568 · 5 จังหวัด` พร้อมกำกับ
`⚠️ ยึดขอบเขตนี้ ไม่ต้องเชื่อปีที่ปรากฏในชื่อไฟล์`

แต่นั่นคือ**การบอกให้โมเดลรู้ ไม่ใช่การบังคับ** — โมเดลยังเลือกตอบด้วยปีอื่นได้
และไม่มีโค้ดจุดไหนเทียบ "ปีที่ผู้ใช้ขอ" กับ "ปีที่มี" แล้วหยุด
(`grep` หา `ไม่พบข้อมูลปี` เจอที่เดียวคือ `accident_chat_sql.py:1161` ซึ่งเป็นสาย
อุบัติเหตุที่ query SQL ตรง ไม่ใช่สาย CSV/vault)

**Citation — มีแล้วฝั่งหน้าเว็บ**
`ApaReferences.tsx` + `obsidianApa.ts` แสดงบรรณานุกรม APA ท้ายคำตอบพร้อมปุ่มคัดลอก
และมีตัวกรองไม่ให้โน้ต MOC ปนเข้ามาเป็นแหล่งอ้างอิง ⇒ **BUG-R2-05 (citation หาย) แก้แล้ว**

ยังขาด: citation แบบ inline ใต้ตัวเลขแต่ละตัว · การ ping ลิงก์ว่ายังเปิดได้ (BUG-004)

### แผนที่เสนอ

1. **ด่านตรวจปีก่อนเข้า pipeline** (1 วัน) — ดึงปีจากคำถามด้วย regex (พ.ศ./ค.ศ. 4 หลัก)
   เทียบกับ `years` ใน `csv_data_dict` ถ้าปีที่ขอไม่มี → คืนข้อความถามกลับทันที
   **ไม่ต้องเรียก LLM เลย** ประหยัดและตอบเร็ว
2. **ตรวจลิงก์ตอนสร้างบรรณานุกรม** (ครึ่งวัน) — `HEAD` request ลิงก์ที่จะอ้าง
   ตายแล้วติดป้ายไว้ ใช้กลไก retry เดียวกับ `hdc_opendata.py` ที่เขียนไว้แล้ว
3. citation inline — ทำทีหลัง กระทบ prompt ทุกโดเมน ความเสี่ยง regression สูง

## 🔴 E10 — Export Formats

### ของจริง — ต้นเหตุ BUG-005 หาเจอแล้ว

`app/journal/page.tsx:109` สร้างไฟล์ด้วย:

```ts
const blob = new Blob(["﻿", wordHtml], { type: "application/msword" })
a.download = `${title}.doc`
```

นี่คือ **HTML ที่เปลี่ยนนามสกุลเป็น `.doc`** ไม่ใช่ไฟล์ Word จริง Word เปิดได้ก็จริง
แต่ตีความ layout เองทั้งหมด ⇒ **คำตกบรรทัด/ตารางเพี้ยนตาม BUG-005 เป็นผลโดยตรง
ของวิธีนี้ ไม่ใช่บั๊กที่แก้ด้วยการปรับ CSS ได้** — ต้องเปลี่ยนวิธีสร้างไฟล์

ไม่มี XLSX · ไม่มี PDF · ไม่มี JPG กราฟ

**แผน:** ใช้ไลบรารีสร้าง `.docx` จริง (เช่น `docx` ของ JS) ฝั่ง server — ประเมิน 2–3 วัน
XLSX ใช้ `exceljs` เพิ่มอีก 1 วัน · PDF/JPG ทำทีหลังได้

## A1 — ทำให้ปุ่มเลือกค่าย AI ตอนแชทสมบูรณ์ 🔴 ด่วน

**ปัญหา:** UI ให้เลือกได้ แต่ **ตัวเลือกถูกเมินใน 6 จาก 7 โดเมน**

| ชั้น | สถานะ |

| Backend รับ | ✅ `analyze.py:160` |

โค้ดเขียนเหตุผลไว้ตรง ๆ ที่ `csv_pipeline.py:592`:

> `chat_provider มีผลกับ d0 เท่านั้น — pipeline CSV/อุบัติเหตุยังใช้ Gemini ตามเดิม

เหตุผลนั้นถูกต้องในเชิงเทคนิค **แต่ผู้ใช้ไม่มีทางรู้** — เลือก Claude แล้วถามเรื่องสถิติ
ก็ยังได้ Gemini ตอบ โดยไม่มีอะไรบอก กลายเป็นปุ่มที่โกหก

> [!danger] อาการนี้แย่กว่าไม่มีปุ่มเลย
> ปุ่มที่กดแล้วไม่เกิดอะไรทำลายความเชื่อถือมากกว่าการไม่มีปุ่ม เพราะผู้ใช้
> จะสรุปว่า "เลือกค่ายไหนก็เหมือนกัน" ทั้งที่ความจริงคือระบบไม่ได้สลับให้

**แผน แบ่ง 2 ขั้น — ขั้นแรกทำได้ทันที**

**ขั้น 1 (ครึ่งวัน) — พูดความจริงก่อน**
ป้ายบอกค่ายที่ตอบจริงมีอยู่แล้วใน SSE (`chatProvider` ที่ `csv_pipeline.py:702`)
แค่แสดงให้เห็นทุกคำตอบ ไม่ใช่เฉพาะ d0 · และเมื่อโดเมนไม่รองรับค่ายที่เลือก
ให้ขึ้นข้อความสั้น ๆ ว่า *"คำถามนี้ใช้เครื่องมือสถิติ ตอบด้วย Gemini"*
— **ยังไม่ต้องแตะ pipeline เลย ความเสี่ยงเป็นศูนย์**

**ขั้น 2 (3–4 วัน) — ขยายให้เลือกได้จริง**
ต้องทำหลัง [[#🔴 E1 — Determinism (ลำดับ 1 ตาม backlog)|E1 ขั้น 1]] เพราะการรวม 13 จุด

ค่ายที่ผ่านค่อยเปิดให้เลือกรายโดเมน — **อย่าเปิดทั้งหมดพร้อมกันโดยไม่ทดสอบ**
คำเตือนในโค้ดเรื่อง tool contract เป็นเรื่องจริง
