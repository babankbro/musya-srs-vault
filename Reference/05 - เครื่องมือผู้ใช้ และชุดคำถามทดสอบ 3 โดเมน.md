## 1. เครื่องมือทั้ง 5 ตัว — ความสามารถโดยละเอียด

ผู้ใช้เลือกจากปุ่มใต้ช่องพิมพ์ที่ `/chat` · **เลือกหลายตัวพร้อมกันได้** ระบบรวมผลให้
ถ้าไม่เลือกเลย = คุยทั่วไป และเลือกค่าย LLM ได้เอง

### 📊 ข้อมูลสถิติ (`stats`)

**ทำอะไรได้:** หาไฟล์ที่เกี่ยว → อ่านโครงสร้างคอลัมน์ → เขียนโค้ด Pandas → รันจริง → สรุปผล
เป็น pipeline 6 agent ที่**คำนวณจากข้อมูลจริง ไม่ใช่ให้ LLM เดาตัวเลข**

**ครอบคลุม 2 แหล่งที่ต่างกันมาก:**

| แหล่ง | ปริมาณ | ช่วงปี | ระดับ |
|---|---|---|---|
| CSV ใน MinIO | **303 ไฟล์** | พ.ศ. 2560–2569 | อำเภอ / หน่วยบริการ |
| PostgreSQL (อุบัติเหตุ) | `fact_accident_event` 112,066 แถว · `mart_province_road` 18,677 แถว | ค.ศ. 2021–2026 | ถนน / อำเภอ |

**สิ่งที่ได้มาพร้อมกับข้อมูล** (จากงาน HDC Sync): คำอธิบายคอลัมน์ภาษาไทย ·
นิยามเชิงปฏิบัติการ (รหัสโรค ICD · รหัส LAB · เกณฑ์ตัดค่า) · ข้อควรระวังอัตโนมัติ ·
วันที่ต้นทางประมวลผลรายจังหวัด

### 🔍 ข้อมูลจากเว็บ (`tavily`)

ค้นเว็บสด ๆ ผ่าน Tavily แล้วสรุปพร้อมลิงก์ · **ไม่จำกัดโดเมนและไม่จำกัดพื้นที่**
เหมาะกับสิ่งที่ข้อมูลในระบบไม่มี เช่น มาตรการล่าสุด · ข่าวนโยบาย · แนวปฏิบัติจากต่างประเทศ

⚠️ เป็นแหล่งเดียวที่**ไม่ผ่านการคัดกรองคุณภาพ** — ใน benchmark ควรนับ claim จากช่องทางนี้
เป็น `Unsupported` เว้นแต่จะตรวจกับ Evidence Pack ได้

### 📖 ฐานข้อมูลวิจัย (`thaijo` / `pubmed`)

ค้นบทความวิชาการ **เลือกได้ทั้ง ThaiJo และ PubMed พร้อมกัน** (รันคู่ขนาน)
มีการห่อ URL เป็นลิงก์อัตโนมัติ และแคชสรุป PDF ไว้บน Redis

| แหล่ง | เหมาะกับ |
|---|---|
| ThaiJo | บริบทไทย · งานวิจัยเชิงพื้นที่ · ภาษาไทย |
| PubMed | หลักฐานเชิงประจักษ์สากล · systematic review · แนวทางคลินิก |

**ไม่จำกัดพื้นที่เขต 10** — ใช้หา evidence base มาสนับสนุนมาตรการได้

### 📚 คลังรายงาน (`obsidian`)

ค้นจากเอกสารที่เขต 10 เขียนไว้เอง — **โหลดทั้งบริบทให้ LLM อ่าน ไม่ใช่ค้นทีละท่อน**

**ครอบคลุม 1,545 โน้ต:**

| จังหวัด | โน้ต | | ประเภท | โน้ต |
|---|---:|---|---|---:|
| ศรีสะเกษ | 329 | | รายงาน (report) | 905 |
| ยโสธร | 311 | | ระดับอำเภอ (district) | 410 |
| อุบลราชธานี | 288 | | สารบัญ (MOC) | 193 |
| อำนาจเจริญ | 259 | | งานวิจัย (research) | 20 |
| ส่วนกลาง | 200 | | นโยบาย (policy) | 16 |
| มุกดาหาร | 157 | | | |

⚠️ **ตัวเลขจากคลังรายงานเป็นตัวเลข ณ วันที่เขียนรายงาน ไม่ใช่ข้อมูลสด**
ระบบมี notice เตือนเรื่องนี้อยู่แล้ว (`accident_redirected_to_obsidian`)

### 📋 แผนหรือนโยบาย (`report`)

**ไม่ใช่แหล่งข้อมูล แต่เป็นตัวประกอบเอกสาร** — ระดมจาก 5 แหล่งพร้อมกันแล้วเรียบเรียง
เลือกชนิดเอกสารได้ 3 แบบ: Policy Brief · Strategic Plan · Work Plan
พร้อมบรรณานุกรม APA อัตโนมัติ และส่งออก DOCX/PDF

## 2. ความครอบคลุมรายโดเมน — **ไม่สมมาตรอย่างรุนแรง**

> [!danger] ข้อค้นพบสำคัญที่สุดของโน้ตนี้
> สามโดเมนของแบบที่ 7 **มีข้อมูลรองรับไม่เท่ากันเลย** ถ้าตั้งคำถาม benchmark
> โดยไม่รู้เรื่องนี้ จะสรุปผิดว่า "ระบบตอบโดเมนอุบัติเหตุได้แย่" ทั้งที่**ข้อมูลไม่มีให้ตอบ**

| โดเมน (แบบที่ 7) | ไฟล์ CSV | ฐานข้อมูล | คลังรายงาน | วิจัย/เว็บ |
|---|---:|---|---|---|
| **D1 อุบัติเหตุ** | **0 ไฟล์** ⚠️ | ✅ star schema | ✅ | ✅ |
| **D2 โภชนาการ + NCDs** | **154 ไฟล์** | ✕ | ✅ | ✅ |
| **D3 สุขภาพจิต** | **101 ไฟล์** | ✕ | ✅ | ✅ |

### D1 อุบัติเหตุ — พึ่ง PostgreSQL อย่างเดียว และมีข้อจำกัดหนัก

**ไม่มีไฟล์ CSV เลยสักไฟล์** (`D1_Road` = 0) ทั้งหมดมาจากฐานข้อมูล

> [!danger] ข้อจำกัดที่ต้องรู้ก่อนตั้งคำถาม
> 1. **`fact_accident_person` ว่างเปล่า (0 แถว)** ⇒ ตอบเรื่อง**หมวกกันน็อก เข็มขัดนิรภัย
>    อายุ เพศ ของผู้ประสบเหตุไม่ได้เลย** — ซึ่งเป็นหัวใจของมาตรการพฤติกรรม
> 2. **`mart_province_road` เป็นข้อมูลทั้งประเทศ** — 92 จังหวัด 904 อำเภอ 18,677 แถว
>    แต่ **เขต 10 มีแค่ 831 แถว = 4.4%** ⇒ ถ้า query ไม่กรองจังหวัด จะได้ตัวเลขทั้งประเทศ
> 3. **ปีเป็น ค.ศ. (2021–2026)** ต่างจาก CSV ที่เป็น พ.ศ. ⇒ ถามเป็น พ.ศ. ต้องแปลง +543

**ข้อมูลที่ใช้ได้จริง:** จำนวนอุบัติเหตุ · บาดเจ็บ · เสียชีวิต · บาดเจ็บสาหัส ·
ชื่อถนน (18,632/18,677 มีค่า) · ประเภทถนน · สาเหตุเด่น · ยานพาหนะเด่น · hotspot score

|---|---:|

**โดเมนนี้พร้อมที่สุดสำหรับ benchmark** — มีทั้งตัวเลข นิยามตัวชี้วัด และคำเตือน

### D3 สุขภาพจิต — 101 ไฟล์ แต่กระจุกตัว

เกือบทั้งหมดอยู่ใต้ `ผู้ป่วยสุขภาพจิต` กลุ่มเดียว (ซึมเศร้า · จิตเภท · ฆ่าตัวตาย ·
SMI-V · ผู้ป่วยนอก/ในจิตเวช · บกพร่องทางสติปัญญา)

⚠️ **ยังมี 52 ไฟล์ทั้งระบบที่ `indicator_th` ไม่ใช่ชื่อจริง** (ดู [[09 - HDC Sync — สถานะงาน]])
ส่วนใหญ่อยู่ในโดเมนนี้ ⇒ File Finder อาจหยิบไฟล์ผิดในคำถามที่เจาะจงมาก

## 5. ข้อควรทำก่อนรัน benchmark จริง

1. **ยอมรับความไม่สมมาตรของโดเมน** — D1 มี 0 CSV ควรลดสัดส่วนคำถามเชิงตัวเลข
   หรือระบุในรายงานว่าข้อจำกัดมาจากข้อมูล ไม่ใช่ความสามารถของ AI
2. **เตรียม Evidence Pack จาก `csv_data_dict`** — มี `definition` · `numerator_th` ·
   `denominator_th` · `caveats` · `date_com` ครบแล้ว ตรงกับที่แบบที่ 7 ต้องการ
3. **ยังไม่มี `plan_period`** (6 เดือน / 1 ปี) ใน `AnalyzeRequest` — แบบที่ 7 บังคับ
4. **บันทึก model version · prompt version · temperature · วันที่รัน** ทุกครั้ง
   ไม่งั้นเทียบผลข้ามรอบไม่ได้
