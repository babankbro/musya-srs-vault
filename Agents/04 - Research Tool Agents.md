# 📖 ขบวนการเอเจนต์ประจำปุ่ม "วิจัย" (Research Tool)

← กลับไป [[03 - Knowledge Tool Agent]] · ตอนถัดไป → [[05 - Web Search Tool Agents]] · ไปดูเส้นทางเวิร์กโฟลว์: [[04 - Research Workflow]]

> ปุ่มงานวิจัยนี้ถูกแบ่งสายวิชาการออกเป็น 2 สำนักใหญ่: สำนัก **ThaiJo** (งานวิจัยไทย) และสำนัก **PubMed** (งานวิจัยแพทย์สากล) (ผู้ใช้สามารถเลือกติ๊กใช้อย่างใดอย่างหนึ่ง หรือจะควบสองเลยก็ได้)
> จุดเด่นของแต่ละสายคือการทำงานแบบลูกผสม: เอา **สคริปต์โค้ด (fetcher)** ทำหน้าที่เป็นตัววิ่งไปกวาดข้อมูล + เอา **เอเจนต์ LLM** มารับช่วงต่อทำหน้าที่วิเคราะห์/สรุป/และเขียนร่าง

## A. สำนัก ThaiJo — พำนักที่ไฟล์ `thaijo_agent.py`

### A0. นักดูดข้อมูล ThaiJo Fetcher (ตัวดึงใช้ httpx + ตัวสรุป/แปลใช้ OpenAI)
ใช้ไลบรารี `httpx` ต่อสายตรงยิงคำขอไปหา **TCI-ThaiJo API** (ผ่านตัวแปร `THAIJO_API_URL`, ตั้งค่ากวาดผลลัพธ์มา 5 เรื่อง) เพื่อสูบเอาบทความ + โหลดตัวหน้ากระดาษ PDF ·
และมีความฉลาดแอบฝากผลงานสรุป PDF ค้างเก็บไว้บนแคชของ Redis (`thaijo_cache.py`) เพื่อความไวในรอบหน้า

> ⚠️ **แก้ให้ตรงโค้ด:** ขั้น "ดึง" ไม่ใช้ LLM (httpx ล้วน) แต่ขั้น **"สรุป PDF" และ "แปลบทคัดย่อ" ใช้ OpenAI จริง** —
> สรุป PDF ด้วย **`gpt-4.1`** (temp 0.3, system prompt `"นักวิจัยด้าน{term}"`) และแปล abstract EN→TH ด้วย
> **`gpt-4.1-mini`** (temp 0.2) → **ต้องตั้ง `OPENAI_API_KEY`** ไม่งั้นขั้นตอนนี้ล้ม (ผลถูก cache บน Redis)

### A1. นักวิเคราะห์สายลึก (Insight Analyst)
- **คิดซ้ำสุด:** 3 รอบ · **อาวุธ tools:** —
- **เป้าหมาย (goal):** *"สแกนวิเคราะห์บทความวิชาการที่สูบมาได้ แล้วสกัดดึงเฉพาะ insight แก่นๆ ออกมาให้ได้"*
- **ปูมหลัง (backstory):** *"คุณคือนักวิเคราะห์ข้อมูลสาธารณสุขระดับอาวุโส เซียนด้านการสังเคราะห์งานวิจัย ... จงสกัด insight เชิงลึก มองหาเทรนด์แนวโน้ม และเขียนข้อเสนอแนะเบื้องต้นมาให้หน่อย"*
- **ความสามารถล้นเหลือ:** เขียนสรุปแจกแจงมา 3 หัวข้อเน้นๆ (ประเด็น/แนวโน้ม · ตัวแปรปัจจัยที่เจอ · ข้อเสนอแนะ) คุมความยาวไม่ให้เกิน 10 บรรทัด และต้องล้อไปกับเนื้อหาแชทเก่า

### A2. มือสรุปความ (Summary Agent)
- **คิดซ้ำสุด:** 2 รอบ · **อาวุธ tools:** —
- **เป้าหมาย (goal):** *"ร่ายสรุปแบบสั้นๆ กระชับๆ ว่ากองบทความที่ไปขุดมาได้นี้ มันพูดถึงเรื่องอะไรกันบ้าง"*
- **ปูมหลัง (backstory):** *"คุณมีหน้าที่รวบยอดผลการค้นหาบทความวิชาการทั้งหมด ให้กลายประโยคภาษาไทยสัก 2-3 ประโยค ที่ชาวบ้านอ่านแล้วเก็ตทันที"*
- **ความสามารถล้นเหลือ:** กางลิสต์รายชื่อบทความโชว์ + ตบท้ายด้วย 1 ประโยคเด็ดที่สรุปใจความรวมทั้งหมด

### A3. คนจัดโครงร่างรายงาน ThaiJo Report Planner (จะตื่นมาทำงานเมื่อโดนสั่งปั้นรายงาน)
- **คิดซ้ำสุด:** 3 รอบ · **อาวุธ tools:** —
- **เป้าหมาย (goal):** *"ร่างแผนที่โครงสร้างของรายงานวิชาการ โดยอิงจากบทความที่พบ ขอแบบกระชับๆ ไม่เยิ่นเย้อ"*
- **ปูมหลัง (backstory):** *"คุณคือบรรณาธิการ (editor) ประจำวารสารวิชาการ ผู้ช่ำชองการคั้นน้ำงานวิจัยสาธารณสุขไทย ... จงร่างเค้าโครงเรื่องที่สมบูรณ์ ชี้เป้า theme หลัก และซอย section ย่อยให้ชัดเจน"*
- **ความสามารถล้นเหลือ:** คายพิมพ์เขียวร่างแผนงานออกมา (มี Theme หลัก 3–5 เรื่อง · ซอย Section ให้ · ชี้ประเด็น discussion ยั่วๆ) คุมความยาวห้ามเกิน 10 บรรทัด

### A4. เครื่องจักรพิมพ์รายงาน Report Generator (สตรีมพ่น HTML)
- **ชนิดพนักงาน:** สายสตรีมยิงตรงผ่าน litellm (ไม่ใช่สไตล์ CrewAI Agent) · เสกคำสั่งพรอมต์มาจากกรุ `thaijo_prompts.build_prompt(doc_type, ...)`
- **ความสามารถล้นเหลือ:** เนรมิต **รายงานหน้าตาเหมือน journal HTML จัดวางแบบกระดาษ A4** (เรียกฟอนต์สารบัญ Sarabun, จัดตัดหน้า page-break สวยๆ, มีองค์ประกอบครบตั้งแต่ บทคัดย่อ/วิธีการศึกษา/ผลลัพธ์/บรรณานุกรมอ้างอิง)
  หน้าตาจะปรับเปลี่ยนไปตามเป้าหมาย `doc_type` (นโยบาย `policy` / แผนยุทธศาสตร์ `plan` / หรือแผนงาน `workplan`) — โดยมีบล็อก CSS แต่งหน้าเทมเพลตซ่อนไว้ที่ `_JOURNAL_CSS` ในไฟล์ `thaijo_prompts.py`
- 🆕 **ด่านบังคับห่อลิงก์ `_linkify_bare_urls()`** — ทำงานหลัง LLM พ่น HTML ออกมาแล้วเสมอ

> [!bug] 🆕 ทำไมต้องมีด่านนี้ ทั้งที่พรอมต์ก็สั่งไปแล้ว
> พรอมต์สั่งให้ห่อ URL ด้วย `<a href>` ทุกครั้ง **แต่มันไม่ deterministic** — บางรอบ (โดยเฉพาะในลิสต์ "เอกสารอ้างอิง") LLM ดันเขียนแค่ `URL: https://...` เป็นข้อความธรรมดา ผู้ใช้กดไม่ได้ทั้งที่ URL ถูกต้อง จึงต้อง post-process บังคับห่อทีหลังเสมอ **ไม่พึ่งพรอมต์อย่างเดียว**
>
> ตัวฟังก์ชันฉลาดพอที่จะ **ไม่ห่อซ้อน** — มันแยกส่วนที่เป็น `<a>...</a>` อยู่แล้วออกไปก่อนด้วย `re.split` แล้วค่อย linkify เฉพาะส่วนที่เหลือ (กัน nested `<a>` ซึ่งเป็น HTML ที่ผิด) และตัดอักขระท้าย URL ที่ไม่ควรติดไปด้วย (`.,;)]`)
>
> 🧪 คุมด้วย `tests/test_thaijo_linkify.py` — รวมบั๊กจริงที่เจอ: รูปแบบ `[URL: http://...]` วงเล็บเหลี่ยมปิดท้ายถูกกลืนเข้าไปเป็นส่วนหนึ่งของลิงก์ ทำให้พาไปหน้าที่ไม่มีจริง

## B. สำนัก PubMed — พำนักที่ไฟล์ `pubmed_agent.py`

### B1. ผู้เชี่ยวชาญสกัดคีย์เวิร์ด (Keyword Extractor)
- **ชนิดพนักงาน:** ยิงตรงหาลูกพี่ Gemini (ผ่านฟังก์ชัน `extract_pubmed_query`)
- **ความสามารถล้นเหลือ:** เปลี่ยนภาษาชาวบ้าน คำถามภาษาไทย → ตีความออกมาเป็น **คำค้นภาษาอังกฤษ / หรือศัพท์แพทย์ MeSH term** เพื่อเอาไปโยนลง PubMed พร้อมอธิบายเหตุผลวิธีคิด (reasoning)

### B2. นักดูดข้อมูล PubMed Fetcher (ใช้โค้ดดิบๆ ไม่พึ่ง LLM)
- รับจ๊อบเรียกท่อ **NCBI E-utilities API** (ผ่านฟังก์ชัน `search_pubmed_progressive(query, retmax, api_key, email)`)
- **ความสามารถพิเศษที่ซ่อนไว้:** ถ้าค้นด้วยชุดคำยาวเหยียดแล้วดันวืด ได้ 0 บทความ → มันจะใช้ลูกตื๊อ **ทยอยหั่นคำศัพท์ (term) ตอนท้ายทิ้งไปทีละคำ** แล้วค้นใหม่เรื่อยๆ จนกว่าจะเจอของ
  (เป็นท่าไม้ตายแก้ปัญหาการยัดเงื่อนไข AND ของศัพท์ MeSH เยอะเกินจนตีกรอบแคบไปทำให้บทความหายเกลี้ยง) · และจะตั้งฟิลเตอร์กรองเอาเฉพาะบทความที่ใจป๋าแจก **อ่านเต็มฟรี (free full text)** เท่านั้น
- หลังจากนั้นจะพ่นผลลัพธ์บทความมาให้ (ชื่อเรื่อง Title/รายชื่อคนแต่ง Authors/วารสาร Journal/รหัส PMID/ลิงก์ URL/และบทคัดย่อ Abstract) → จับโยนสตรีมออกเป็นข้อความ

> [!note] ข้อควรรู้เมื่อเปิดโหมด research (วิจัยควบสองฝั่ง)
> ถ้าผู้ใช้โลภมาก สั่งติ๊กค้นทั้ง ThaiJo + PubMed คู่กัน (โหมด `mode=research`) ไฟล์ลูกพี่ใหญ่ `analyze.py` จะจัดให้โดยเปิดท่อรัน 2 pipeline **แบบคู่ขนานพร้อมกัน**
> (ใช้ท่า `ThreadPoolExecutor(2)`) แล้วเอาผลที่ได้มาปะติดปะต่อกันทีหลัง — ข้อมูลบทความเนื้อๆ จะถูกกวาดเก็บไว้ในตัวแปร `articles_text` เพื่อรอประเคนส่งต่อให้ลูกพี่ [[06 - Report & Policy Agents|report generator]] ดึงไปอ้างอิงร่ายยาวต่อไป
