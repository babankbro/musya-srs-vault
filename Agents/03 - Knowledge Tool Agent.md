## ขุนคลัง Obsidian Full-Context "Agent" (พำนักที่ไฟล์ `obsidian_fullcontext.py`)

**ชนิดพนักงาน:** สายยิงตรงหา Gemini (ไม่ได้ปั้นคลาสเป็น `Agent()` แบบของ CrewAI)
**วิธีหาเสบียงข้อมูล:** มันจะไปควานหาอ่านโน้ตมาจากตาราง **`obsidian_notes` (ใน PostgreSQL)** — ถ้าผู้ใช้ถามเจาะจงจังหวัด ก็จะกรองดึงมาเฉพาะของจังหวัดนั้น (กินพื้นที่ราวๆ ~100–200 KB) แต่ถ้าถามหว่าน ก็จะหอบมาทั้งคลัง vault เลย (ขนาดบิ๊กเบิ้ม ~1.1 MB) โดยมีสวิตช์เบรกเกอร์ตัดบทที่ `OBSIDIAN_MAX_CONTEXT_CHARS = 500000` (ตัดตัวอักษรส่วนเกินทิ้งกันเซิร์ฟระเบิด)

### เจาะลึกคาถาสะกดจิต (SYSTEM_PROMPT) — สรุปใจความสำคัญ
> *"คุณคือศาสตราจารย์ผู้เชี่ยวชาญด้านข้อมูลสุขภาพ ประจำเขตสุขภาพที่ 10 (ครอบคลุม อุบลราชธานี, ศรีสะเกษ, ยโสธร,
> อำนาจเจริญ, มุกดาหาร) ... กติกาเหล็กคือ ขอให้ตอบโดยอ้างอิงเนื้อหาจากเอกสารที่เราแนบไปให้เหล่านั้นเท่านั้น"*

**แม่พิมพ์รูปแบบคำตอบที่ถูกบังคับ (สไตล์ Markdown):**
1. **ส่วนสรุปคำตอบ** — ขอแบบเนื้อเน้นๆ 2–3 ประโยค ตอบตรงประเด็นไม่อ้อมค้อม
2. **ส่วนข้อมูลจากคลังความรู้** — ถ้ามีตัวเลขให้งัดมาโชว์ในรูปแบบ ตาราง/หรือลิสต์รายการ
3. **ส่วนบริบทและการวิเคราะห์** — ขอแง่มุมวิเคราะห์เชิงลึกสัก 2–3 ประเด็น

**กฎเหล็กแห่งความทนทาน (ความสามารถ + สิ่งที่ห้ามทำเด็ดขาด):**
- ต้องหยิบคำตอบมาจากเนื้อหาในเอกสารล้วนๆ — **ห้ามเสกตัวเลขขึ้นมาเองเด็ดขาด** (No Hallucination)
- ถ้างมหาในคลังแล้วไม่เจออะไรเลย → ให้สารภาพบาปไปว่า *"ไม่พบข้อมูลในคลังความรู้"* + พร้อมเสนอแนะคำใบ้คำค้นหาใหม่ๆ ให้ผู้ใช้
- **ต้องเปลี่ยนเลขปี ค.ศ. → กลับมาเป็น พ.ศ. เสมอ** ให้คนไทยอ่านง่าย
- ห้ามพิมพ์หัวข้อ "แหล่งข้อมูล" แปะมาในคำตอบ (เดี๋ยวระบบแอปจะเสกโชว์ป้าย `notes_referenced` แปะท้ายลิงก์ให้เอง)
- ก่อนจบคำตอบ ให้ห้อยท้ายทิ้งทวนด้วย **คำถามชวนคุยต่อ (follow_ups) 2–3 ข้อ** เพื่อล่อให้ผู้ใช้อยากกดถามต่อ
- กรณีที่มี "ประวัติแชทความหลัง" แนบไปด้วย → ต้องทำตัวเนียนๆ ตอบสานต่อเป็นเรื่องเดียวกัน (ถ้าเป็นคำถาม follow-up ก็ขอให้ตอบสั้นๆ ชี้เป้าเฉพาะจุดที่เขาสงสัยเพิ่ม ไม่ต้องร่ายยาวใหม่หมด)

### ผลผลิตที่คายออกมา (Output)
ปั้นก้อนร่าง `ObsidianAskResponse(content, notes_referenced[], follow_ups[])` — แล้วแปลงเป็นสายน้ำสตรีมพ่นกลับไปหาเบราว์เซอร์ผ่านท่า SSE

### สรุปรวมขีดความสามารถ
| ด้านความเก่งกาจ | รายละเอียด |
|---|---|
| สายค้นหาเป้าหมาย | มีระบบตีคะแนนความเกี่ยวข้อง `_relevance_score` (คำนวณจากน้ำหนักคีย์เวิร์ด × ความลึกของ path) เพื่อคัดโน้ตเด็ดๆ ก่อนโหลดไปให้ AI อ่าน |
| สายโต้ตอบ | Gemini โชว์พลังสมองอ่านเนื้อหาเต็มๆ (context เต็ม) → ย่อยมาเป็นโครงคำตอบ 3 ส่วน + แปะแหล่งที่มาของโน้ต + แนะนำคำถามล่อเป้า follow-ups |
| สายกันการมั่วเพ้อเจ้อ (hallucinate) | ตรึงพฤติกรรมบังคับให้ลอกคำตอบมาจากเอกสารเท่านั้น + พกยันต์ `dedupe_repeated_answer` กันอาการ AI เมากาวตอบประโยคเดิมซ้ำๆ |

> [!note] จุดแตกต่างจากช่องทาง Search API แบบปกติ
> ต้องแยกให้ออกนะครับว่าปุ่มแชทหน้าจอนี้ใช้วิชา "full-context" (เหมาเนื้อหาโยนให้ Gemini อ่านทั้งก้อน) — แต่ถ้าไปมุดใช้ช่องทาง `POST /api/obsidian/search`
> อันนั้นจะไปปลุกตัว `tools/obsidian.py` ให้ทำงานด้วย **pg_trgm ซึ่งสืบค้นด้วยสคริปต์เพียวๆ ไม่ใช้พลังของ LLM เลยแม้แต่น้อย** (ใช้ท่า Tier1 หาเป็นก้อน chunk + ไต่ตาม wikilink, ถ้าไม่เจอค่อยงัดท่า Tier2 สาดเวทมนตร์ LIKE หาคลุมๆ)
> แวะไปดูเชิงลึกต่อที่ [[03 - Knowledge Vault Workflow]] และผังดาต้าที่ [[04 - Data Architecture & Schema]]
