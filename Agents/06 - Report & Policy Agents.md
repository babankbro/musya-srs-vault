# 📋 ขบวนการเอเจนต์ประจำปุ่ม "สร้างรายงาน" และงานเชิงนโยบาย

> มีความลับจะบอก: ปุ่มกด **สร้างรายงาน** (`report-gather`) หน้าจอแชทน่ะ จริงๆ แล้ว **ไม่ได้มีตัวเอเจนต์งอกใหม่มารับงานหรอกนะ** — แต่มันแอบใช้ท่าปลุกชีพสั่งรัน 5 pipeline ยอดฮิตของเดิม
> (ไล่ตั้งแต่ [[02 - Stats Tool Agents|แก๊งสถิติ]] · [[03 - Knowledge Tool Agent|คลังความรู้]] · [[04 - Research Tool Agents|ThaiJo/PubMed]] · จนถึง [[05 - Web Search Tool Agents|ตัวค้นหา Tavily]]) ให้ตื่นขึ้นมาทำงานพร้อมๆ กันแบบคู่ขนาน
> พอกวาดของมาได้ครบ ก็จะปล่อยให้เป็นหน้าที่ของ **ตัวช่วย wizard บนฝั่งหน้าจอ (UI)** จัดการจับของทั้งหมดมาหยอดประกอบร่างเป็นรายงานเล่มสวยงาม · สรุปก็คือ โน้ตหน้านี้จะเป็นการรวบรวมแก๊งเอเจนต์ "สายนางแบกรับจ๊อบเขียนรายงาน/ทำแผนงาน/ร่างนโยบาย" 
> ที่ถูกเรียกใช้งานผ่านสายเฉพาะกิจ (อาทิ `/api/report`, `/api/workplan`, `/api/compare`, `/api/database`, และ `/api/accident-policy/zone10`) มารวมไว้ด้วยกัน

## A. วงประชุมนโยบายเขต 10 (Zone 10 Policy Brief) — พำนักที่ `accident_policy_agent.py` (รุม 3-agent, วิ่งเป็น Crew ตามลำดับ)

### A1. คนสวนเก็บข้อมูล Zone 10 SQL Data Fetcher
- **อาวุธ tools:** พกคลังแสง `ZONE10_TOOLS` (ประกอบด้วยดาบ SQL 7 เล่ม ส่งตรงจาก `zone10_accident.py`) · **คิดซ้ำสุด:** 10 รอบ (ให้โควต้าเยอะหน่อยเผื่อเจอบั๊ก)
- **เป้าหมาย (goal):** *"เดินหน้าดึงกวาดข้อมูลสถิติอุบัติเหตุทางถนนในเขตสุขภาพที่ 10 ให้เกลี้ยง โดยต้องงัดเครื่องมือทั้ง 7 ตัวออกมาใช้ให้ครบถ้วน"*
- **ปูมหลัง (backstory):** *"คุณคือปรมาจารย์ด้านฐานข้อมูลอุบัติเหตุ มีหน้าที่ดึงตัวเลขดิบมาวางกองไว้ให้ครบเป๊ะๆ รายงานไปตามที่ตัวเลขมันฟ้อง **ห้ามทำอวดเก่งตีความหรือแต่งเรื่องสรุปเอาเองเด็ดขาด**"*

### A2. นักวิเคราะห์นโยบาย Zone 10 RTI Policy Analyst
- **คิดซ้ำสุด:** 8 รอบ · **อาวุธ tools:** —
- **เป้าหมาย (goal):** *"จับข้อมูลดิบมาขยำวิเคราะห์ด้วยกรอบทฤษฎี **Haddon Matrix** (ก่อน-ขณะ-หลังเกิดเหตุ) แล้วจัดหมวดหมู่ยัดเข้า 4 กล่องนโยบาย พร้อมคายผลลัพธ์ออกมาเป็นโครงสร้าง JSON structured analysis"*
- **ปูมหลัง (backstory):** *"คุณคือยอดนักวิเคราะห์นโยบายความปลอดภัยทางถนนระดับเขต ... สิ่งสำคัญคือต้องมีเส้นแบ่งชัดเจน แยก 'ก้อนข้อเท็จจริงดิ้นไม่ได้' ออกจาก 'บทวิเคราะห์ตีความ' อย่างเป็นระบบ"*

### A3. เสมียนร่างรายงานนโยบาย Zone 10 RTI Policy Report Writer
- **คิดซ้ำสุด:** 6 รอบ · **อาวุธ tools:** —
- **เป้าหมาย (goal):** *"จรดปากกาเขียนรายงานนโยบายแก้ปัญหาอุบัติเหตุของเขต 10 โดยให้ออกมาในรูปลักษณ์ **รายงานการตรวจราชการ** ที่มีองค์ประกอบครบ 5 ส่วนหลักเป๊ะๆ"*
- **ปูมหลัง (backstory):** *"คุณคือเสมียนเอกผู้ช่ำชองการเขียนภาษาราชการสายสาธารณสุข ... กฎประหารคือ **ต้องหยิบใช้เฉพาะก้อนข้อมูลที่ได้รับส่งต่อมาจากตัว Analyst ด้านบนเท่านั้น**"*

> ช่องทางเข้าถึง: สั่งรันผ่านเส้นทาง `POST /api/accident-policy/zone10` (จิบกาแฟรอได้เลยเพราะกระบวนการนี้กินเวลา 2–5 นาที)

## B. นักเขียนรายงานสรุปผู้บริหาร Report Writer — พำนักที่ `report_agent.py` (`/api/report`)
ลำดับการวิ่งผลัด: **หน่วยค้นไฟล์ (File Finder) → นักวิเคราะห์ข้อมูล (มือปั้นโค้ด) → ห้องประหารรันโค้ด Python → จบที่ตัวเขียนรายงาน Report Writer**

- **นักเขียนรายงาน Report Writer — (สวมหมวก Thai Public Health Analyst)** · คิดซ้ำสุด 5 รอบ · อาวุธ tools —
- **เป้าหมาย (goal):** *"ปั้นรายงานบทสรุปผู้บริหารเป็นภาษาไทยที่เนื้อหาแน่นเปรี๊ยะ โครงสร้างเคลียร์คัท โดยกลั่นกรองมาจากผลการรันวิเคราะห์ข้อมูลจริงเท่านั้น"*
- **ปูมหลัง (backstory):** คาถาสะกดจิต `join_prompt("คุณคือนักวิเคราะห์นโยบายสายเก๋า ... ต้องวาดตาราง markdown โชว์ตัวเลขจริง + ชี้แนะแนวทางนโยบายที่เอาไปทำได้จริงบนโลกใบนี้ ... กฎเหล็กคือห้ามละสายตาจาก Execution Result — ห้ามเสกมโนสร้างข้อมูลผีขึ้นมาหลอกกัน", ANALYST_CORE_POLICY)`

## C. นักวิเคราะห์แผนงาน Plan Analyzer — พำนักที่ `workplan_agent.py` (`/api/workplan`)
ลำดับการวิ่งผลัด: **นักวิเคราะห์แผน Plan Analyzer (ฝั่ง CrewAI) → ช่างเขียนแผน Plan Writer (ยิง litellm พ่นเป็นสตรีม HTML ตรงๆ)**

- **นักวิเคราะห์แผน Plan Analyzer — (สวมหมวก Thai Public Health Work Plan Specialist)** · คิดซ้ำสุด 5 รอบ · อาวุธ tools —
- **เป้าหมาย (goal):** *"ชำแหละโจทย์หัวข้อ แล้วเสกโครงสร้างแผนงานที่สมบูรณ์แบบออกมา ต้องชี้เป้าวัตถุประสงค์ ระบุกลุ่มเป้าหมาย กางลิสต์กิจกรรม และตั้งตัวชี้วัดที่จับต้องได้"*
- **ปูมหลัง (backstory):** *"คุณคือมือโปรด้านการวางแผนงานสาธารณสุขประจำจังหวัด/เขต ... ถนัดเรื่องการผูกแผน เคาะงบประมาณ และตั้งตัวชี้วัดล้อตามระบบมาตรฐาน **BSC (Balanced Scorecard)**"*
- **ความสามารถล้นเหลือ:** เก่งกาจรองรับโหมด `doc_type` ได้หลากหลายรูปแบบ — เช่นสั่ง `workplan`=เสกแผนปฏิบัติการ · สั่ง `plan`=เสกแผนยุทธศาสตร์ · หรือสั่ง `policy`=เสกแผนนโยบาย;
  หลังจากนั้นตัวช่างเขียนแผน (Plan Writer) จะรับช่วงต่อ เนรมิตเอกสาร HTML ยาวเหยียดอลังการกว่า ~15 หน้า (โดยอิงเบ้าหลอมเทมเพลตที่ชื่อ `PROMPT_PLAN`)

## D. ลานประลองเปรียบเทียบ / งัดกระดองตาราง Compare / Database (ซ่อนอยู่ที่ `/api/compare`, `/api/database`)

### ตี้ `compare_agent.py` — ท้าชนเปรียบมวย 2 ชุดข้อมูล (วิ่งผลัด 6 ด่าน)
- **หน่วยค้นไฟล์ A (File Finder A)** / **หน่วยค้นไฟล์ B (File Finder B)** — แบ่งกำลังไปควานหาชุดข้อมูลที่หนึ่ง และที่สองตามลำดับ (พก tools ค้นไฟล์ไปตัวละอัน)
- **มือปั้นโค้ด Python — (สวมหมวก Data Comparison Specialist)** — นั่งปั่นโค้ดจับข้อมูลมาชนกัน (join) / หาจุดต่าง (diff) / งัดสูตรสถิติ
- **นักวิเคราะห์สายลึก Insight Analyst — (สวมหมวก Data Comparison Expert)** — นั่งแท่นเขียนเล่มรายงานเปรียบเทียบ (บรรยายผลการชน join / หาความสัมพันธ์ / ร่ายผลการทดสอบสถิติ)

### ตี้ `database_agent.py` — เจาะตับวิเคราะห์ไฟล์ที่ผู้ใช้อัปโหลดแนบมาเอง (วิ่งผลัด 4 ด่าน, ตัดด่านควานหาไฟล์ทิ้ง)
- **นักอ่านเอกสาร Document Analyst — (สวมหมวก Thai Language Expert)** — ทำความเข้าใจเจตนาไฟล์แนบ
- **มือปั้นโค้ด Python — (สวมหมวก User File Analyst)** — รัวคีย์บอร์ดเขียนโค้ดเตรียมวิเคราะห์
- **นักวิเคราะห์สายลึก Insight Analyst — (สวมหมวก CSV Data Expert)** — ร่ายบทสรุปปิดจ๊อบ
- **เงื่อนไขการตื่นทำงาน (trigger):** เมื่อไหร่ก็ตามที่ผู้ใช้แชทกดแนบไฟล์เข้ามาในวงสนทนา → ระบบจะดีดตัวเข้าสู่โหมด `database` ให้แบบอัตโนมัติทันที
