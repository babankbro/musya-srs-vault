## UC-15 — ระบบบริหารจัดการไฟล์และการสกัดบรรณานุกรม APA (Manage files & generate APA citation)

- **ผู้ดำเนินการ (Actor):** ผู้ใช้งาน (User)
- **เป้าหมาย (Goal):** จัดเก็บไฟล์เอกสารต้นทางที่ตนเองถือครองเอาไว้ในระบบ และให้ AI ช่วยสกัดข้อมูลแปลงเป็นบรรณานุกรมแบบ APA ที่ถูกต้องให้อัตโนมัติ
- **เงื่อนไขเริ่มต้น (Preconditions):** อยู่ในสถานะเข้าสู่ระบบเรียบร้อย
- **จุดกระตุ้น (Trigger):** ผู้ใช้เปิดเข้าไปหน้าจัดการ `/fileapa` และลากไฟล์เข้ามากดอัปโหลด

**ขั้นตอนหลัก (Main flow)**
1. ผู้ใช้อัปโหลดไฟล์ต้นทาง (รองรับนามสกุลครอบคลุม PDF/DOCX/CSV/XLSX); ระบบผ่านทางด่าน BFF จะนำก้อนไฟล์เหล่านี้ไปฝากขังไว้ในระบบเซิร์ฟเวอร์ Object Storage ภายใน (MinIO ถังชื่อ `fileapa`)
2. ระบบทำการล้วงลึกเข้าไปในเนื้อหาไฟล์ (แกะข้อมูล Metadata) โดยวิ่งผ่านท่อ `/api/generate-apa` เพื่อดึงชื่อผู้แต่ง ปีที่พิมพ์ ฯลฯ และผลิตเป็น **ข้อความอ้างอิงรูปแบบ APA (APA citation string)** ติดป้ายกำกับเก็บคู่ไว้กับไฟล์นั้นไปตลาดกาล
3. ผู้ใช้สามารถเรียกดูหน้ารายชื่อไฟล์ทั้งหมด ดูข้อมูลสกัดเจาะลึก Metadata ที่ AI ค้นพบ และอินไซต์เชิงสถิติได้
4. ผู้ใช้สามารถจัดการลบไฟล์ของตนเองทิ้งได้หากต้องการ

**สถานการณ์ข้อยกเว้น (Alternate / exception)**
- 2a. **การสกัดข้อมูล Metadata ออกมาได้ไม่ครบถ้วน (เช่น ไฟล์ไม่มีชื่อผู้แต่ง):** → ระบบจะสร้างบรรณานุกรมแบบปะติดปะต่อเท่าที่มีไปก่อน และอนุญาตให้ผู้ใช้มานั่งแก้ไขกรอกเพิ่มเอาเองภายหลังได้
- 3a. **ฟังก์ชันขั้นสูง การรวมกลุ่มไฟล์ (Merge multiple files):** → สามารถสั่งการค้นหาไฟล์ → สั่งวิเคราะห์พร้อมกัน → สั่งประมวลผล → และเซฟรวบยอดออกมาเป็น Dataset องค์ความรู้ใหม่ (ตามสเปก FR-FILE-04)

**เงื่อนไขสุดท้าย (Postconditions):** ฝากไฟล์เข้าสู่ระบบอย่างปลอดภัย; การอ้างอิง APA ถูกเตรียมพร้อมให้หยิบไปแปะลงในตัวรายงาน Report ได้ทันที
**อ้างอิงถึงข้อกำหนด:** FR-FILE-01, -02, -03, -04.

## UC-16 — ท่องแดนคลังความรู้ระดับองค์กร (Browse the knowledge vault)

- **ผู้ดำเนินการ (Actor):** ผู้ใช้งาน (User)
- **เป้าหมาย (Goal):** เปิดประตูเข้าไปสำรวจอ่านเอกสารความรู้ (Notes) ของเขตพื้นที่สุขภาพที่ 10 ด้วยตาตนเอง และกดดูไฟล์ PDF ต้นฉบับ
- **เงื่อนไขเริ่มต้น (Preconditions):** ล็อกอินแล้ว; และคลังข้อมูลต้องผ่านการทำดัชนี (Indexed) มาก่อน
- **จุดกระตุ้น (Trigger):** ผู้ใช้เปิดเมนูเข้าสู่ `/musyaend/obsidian`

**ขั้นตอนหลัก (Main flow)**
1. ผู้ใช้ใช้ช่องค้นหาโน้ต (ใช้คำค้นธรรมดา ทฤษฎี Trigram/keyword โดยไม่ต้องรบกวนพลังของ LLM) หรือตั้งคำถามลึกๆ ให้อ่านจากบริบททั้งหมด (Full-context question)
2. ผลลัพธ์การค้นหาเด้งขึ้นมาโชว์รายการโน้ตยิบย่อย พร้อมป้ายกำกับจังหวัด/และชนิดเอกสารอย่างเป็นระเบียบ
3. ผู้ใช้คลิกเปิดอ่านเนื้อหาโน้ตนั้น และถ้าบังเอิญมีข้อมูลที่แนบอิงไว้ด้วย ก็สามารถคลิกดู **เอกสารไฟล์ PDF ต้นฉบับ (Source PDF)** โหลดตรงจากเซิร์ฟเวอร์ MinIO มาปรากฏได้ทันที

**สถานการณ์ข้อยกเว้น (Alternate / exception)**
- 1a. **ระบบคลังยังไม่ได้เรียบเรียงทำดัชนี (Vault not indexed):** → การค้นหาจะไม่ทำงาน เจ้าหน้าที่หลังบ้าน Operator ต้องกดรันคำสั่งทำดัชนีสร้างฐานข้อมูลให้เสร็จสิ้นก่อน (FR-KB-03)
- 3a. **ไฟล์ PDF ยังไม่ได้ซิงโครไนซ์เข้าระบบ:** → หน้าโน้ตนั้นก็จะโชว์แค่ข้อความเฉยๆ ไม่มีลิ้งก์กดดูตัว PDF (FR-KB-04)

**เงื่อนไขสุดท้าย (Postconditions):** ผู้ใช้สามารถหาคำตอบและอ่านบริบทองค์ความรู้จนเข้าใจแจ่มแจ้ง
**อ้างอิงถึงข้อกำหนด:** FR-KB-01, -02, -05.

### เส้นทางการทำงานลับเฉพาะเจ้าหน้าที่ควบคุม (Operator sub-flow) — สำหรับจัดทำระบบ FR-KB-03/04
> เจ้าหน้าที่ระบบสามารถเข้ามารันคำสั่งอัปเดตดัชนีคลังข้อมูล (ยิง API `POST /api/obsidian/index`) เพื่อเรียบเรียงและทำ Chunking โน้ตยัดลงฐานข้อมูลตาราง `obsidian_vaults/notes/chunks/links`
> จากนั้นก็สั่งให้ดึง PDF (`POST /api/obsidian/pdfs/sync`) เพื่อผลักไฟล์ PDF ดิบโยนเข้าเซิร์ฟเวอร์ MinIO และลงทะเบียนเก็บพาธของตัวไฟล์ลงตาราง `obsidian_pdf_assets` แบบเสร็จสรรพ

## UC-17 — เครื่องมือสอดส่องลึกลงฐานข้อมูล (Explore the database)

- **ผู้ดำเนินการ (Actor):** ผู้ใช้งาน (User - หรือนักวิเคราะห์ระดับสูง)
- **เป้าหมาย (Goal):** ต้องการมองทะลุลงไปในตารางความจริงระดับข้อมูลดิบ (Underlying tables) เพื่อทำความเข้าใจหรือตรวจสอบความแม่นยำของผลลัพธ์
- **เงื่อนไขเริ่มต้น (Preconditions):** ต้องล็อกอินอยู่ในระบบ
- **จุดกระตุ้น (Trigger):** ผู้ใช้เข้าสู่เมนูลับ `/musyaend/db-explorer`

**ขั้นตอนหลัก (Main flow)**
1. ผู้ใช้เลือกดูรายชื่อตาราง (Tables), จากนั้นก็ดูชื่อคอลัมน์ (Columns), และกางดูเนื้อหาข้อมูลในตารางแบบแบ่งเป็นหน้าๆ (Paginated rows)
2. ระบบจะตรวจสอบและป้องกันไม่ให้พิมพ์ชื่อที่อันตรายหลุดเข้ามา และถ้ามีคอลัมน์ที่เป็นตัวเลขเวกเตอร์หน้าตายาวๆ กวนตา (Oversized vector fields) ระบบจะฉลาดพอที่จะหั่นลบซ่อนมันไว้ ไม่ให้รกจอ

**สถานการณ์ข้อยกเว้น (Alternate / exception)**
- 2a. **มีการพิมพ์ชื่อตาราง/คำค้นที่เสี่ยงเจาะระบบ:** → ปฏิเสธการค้นหาทิ้งไป (เนื่องจากเครื่องมือนี้ให้อ่านได้อย่างเดียว (Read-only) และมีกลไกป้องกันการแฮกเจาะระบบ SQL Injection ไว้ 100%)

**เงื่อนไขสุดท้าย (Postconditions):** ผู้ใช้สบายใจขึ้นเพราะได้เห็นกับตาและตรวจสอบสถิติเชิงโครงสร้างสำเร็จ โดยไม่มีข้อมูลในฐานล่มสลาย
**อ้างอิงถึงข้อกำหนด:** FR-OPS-01, NFR-SEC-07.

## UC-18 — ทบทวนบันทึกข้อผิดพลาด (Review agent errors - งานระดับปฏิบัติการ)

- **ผู้ดำเนินการ (Actor):** ผู้ดูแลระบบ (Admin) / เจ้าหน้าที่ควบคุม (Operator)
- **เป้าหมาย (Goal):** เพื่อเข้ามาตรวจเช็คหาสาเหตุอาการป่วยของ AI ในเส้นท่อไปป์ไลน์ต่างๆ
- **เงื่อนไขเริ่มต้น (Preconditions):** ล็อกอินและมีสิทธิ์เข้าถึงมุมมองสำหรับฝ่ายปฏิบัติการ
- **จุดกระตุ้น (Trigger):** เปิดเข้าหน้าจอดู Error-log (`/api/errors`)

**ขั้นตอนหลัก (Main flow)**
1. ผู้ควบคุมระบบสามารถเห็นรายการความล้มเหลว (Agent errors) ที่เพิ่งเกิดขึ้น โดยแบ่งลิ้นชักตามประเภทอาการชัดเจน (ตกเรื่อง Auth/ชนโควต้า/รัน Timeout/ก้อนข้อมูลว่างเปล่า/เครื่องมือ Tool พัง)
2. ผู้ควบคุมระบบร้องขอให้ LLM เขียนสรุปรายงานภาพรวมและสถิติปัญหาทั้งหมดเป็นภาษาไทย

**สถานการณ์ข้อยกเว้น (Alternate / exception)**
- 2a. **ไม่มีข้อผิดพลาดเกิดขึ้นเลย:** → โชว์รายงานที่ว่างเปล่า สะอาดตา

**เงื่อนไขสุดท้าย (Postconditions):** ผู้ควบคุมระบบจับสาเหตุพฤติกรรมพังๆ ครั้งล่าสุดของระบบได้ทันท่วงที
**อ้างอิงถึงข้อกำหนด:** FR-OPS-02, -03; NFR-MNT-01.

> [!note] ข้อเสนอแนะเชิงระบบที่ยังทำไม่เสร็จ (Known gap)
> การพอกพูนของแฟ้มระบบ `error_logs/` เกิดขึ้นทุกวัน และยังคงสะสมไปเรื่อยๆ เนื่องจากไม่ได้ตั้งขีดจำกัดการทิ้งข้อมูล (No retention policy: DR-LIFE-04) — แนะนำอย่างยิ่งให้หาเวลาสร้างกระบวนการรันสคริปต์ทำความสะอาดลบทิ้งข้อมูลเก่าๆ

## สรุปเงื่อนไขข้อยกเว้นที่วิ่งแทรกข้ามกันในทุกระบบวิเคราะห์ (Cross-cutting exception behaviours)

กฎเหล็กเหล่านี้จะถูกเปิดใช้งานเหมือนกันหมด ไม่ว่าคุณจะเลือกไปป์ไลน์ตัวไหนก็ตาม:

| สถานการณ์ที่เป็นปัญหา (Condition) | พฤติกรรมที่ระบบจะกระทำตอบโต้ (System behaviour) | รหัสอ้างอิง (Trace) |
|---|---|---|
| เป็นคำขอที่ไม่มีตราประทับเข้าสู่ระบบ (Unauthenticated) | 401 (API) / เตะกลับไปหน้าเข้าสู่ระบบ `/login` (บนหน้าเว็บ) | FR-AUTH-09 |
| ไปเสิร์ชหาพื้นที่นอกเขต จังหวัดที่ 10 | แจ้งปฏิเสธอย่างชัดเจน "ไม่มีข้อมูล" + พร้อมลิสต์ว่าจังหวัด 5 แห่งที่หาได้คืออะไร; ตัวปัญหานี้จะถูกจับบันทึกลง Log | FR-CHAT-08 |
| คนแย่งกันรัน Pipeline เต็มโควต้า (เกิน 5 คนต่อ 1 เวิร์กเกอร์) | ขึ้นข้อความอ้อนวอนผู้ใช้ "ระบบกำลังยุ่งหนัก ให้ลองใหม่ทีหลัง" | FR-CHAT-15, NFR-PERF-02 |
| ตัวเซิร์ฟเวอร์ Google Gemini เน่า / โควต้าเต็ม 429/503 | ระบบจะทดลองวิ่งชนตื๊อหน่วงเวลาเป็นจังหวะกระตุก (Bounded exponential backoff), หากไม่ไหวจริงๆ ค่อยเทลง Log | NFR-REL-01 |
| สายฝั่งลูกข่ายหลุด/ปิดเน็ต ระหว่างการสตรีมคำตอบ | ตัวกลาง BFF ของเราจะคอยเซฟคำตอบสุดท้ายที่วิ่งมาลงฐานข้อมูลฝั่งเซิร์ฟเวอร์ไว้ เผื่อผู้ใช้เข้ามาดูใหม่ตอนหลัง | FR-CHAT-14, NFR-REL-03 |
| พิมพ์ระบุปีเป็น พ.ศ. ตอนหาอุบัติเหตุ | จับหั่นแปลงเป็นระบบ ค.ศ. ทุกครั้ง ก่อนนำลงไปสืบค้นในดาต้าเบส | FR-CHAT-09, DR-ACC-YEAR |
