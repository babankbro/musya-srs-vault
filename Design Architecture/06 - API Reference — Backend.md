# 📡 คู่มืออ้างอิง API ฝั่ง Backend (ของโปรเจกต์ `chatapi.python`) แยกจำแนกตามรายไฟล์

← [[05 - File Structure Tree]] · อ่านควบคู่กับ → [[07 - API Reference — Frontend (BFF)]] · อ้างอิงสเปกเดิม: [[04 - External Interface Requirements]]

> เอกสารชุดนี้ถูกจัดทำขึ้นมาเพื่อไล่อธิบายเจาะลึก **ระบบสั่งงาน API ทีละเส้น ทีละไฟล์ในส่วนของตัวรับแขก router** (ที่อยู่ในโฟลเดอร์ `src/routers/*.py`) แกะแบบมาจากโค้ดต้นฉบับจริงทุกบรรทัด
> (เช่นการแปะป้ายตัวสัญลักษณ์ decorator `@router` + รูปแบบ Pydantic schema) — จัดเรียงระบุชนิดการเรียก Method, เส้นทาง Path, สิ่งที่ต้องส่ง Request, สิ่งที่ตอบกลับ Response และหมายเหตุข้อควรระวัง
> **ข้อมูลฐาน URL ที่ควรรู้:** `http://python-ai:8000` (เป็นชื่อเรียกกันในเครือข่ายภายในคอนเทนเนอร์) / หรือ `http://localhost:8000` (หากรันจากฝั่งคอมพิวเตอร์ dev) · ส่วนหน้ากากชี้เป้า Swagger ลองไปที่: `/docs`
> **คำเตือนตัวโตๆ (สำคัญสุด):** ชาวบ้านผู้ใช้ทั่วไปหรือหน้าเว็บฝั่งนอก จะกระโดดมาเรียกตรงๆ ไม่ได้เลย โดนบล็อกแบนสนิท ต้องตีตั๋วผ่านประตูหน้าด่าน BFF เพื่อให้สวมหน้ากากแนบรหัสลับ `x-internal-key` มาให้เท่านั้น (อ่านเพิ่มที่ [[07 - API Reference — Frontend (BFF)]])

รูปแบบการตอบกลับพ่นน้ำลายของระบบที่พบบ่อยๆ: 
- ท่า **SSE** = ตอบเป็นสายธารข้อมูลสตรีม `text/event-stream` (จะไหลแจ้งจังหวะหายใจของโมเดลผ่านชื่อ event ว่า `agent_start` รอเกิด / `agent_done` ทำเสร็จจุดนึง / `text_chunk` แหว่งข้อความออกมา / `result` สรุปกลางทาง / `final` สรุปจบบริบูรณ์ / หรือ `error` ร่วงตาย) 
- ท่า **JSON** = ตอบฟรึ่บ โยนออกมาเป็นก้อนตู้มเดียวจบ

## 1. `analyze.py` — ด่านปราการประตูหน้าหลักของระบบแชท (tags: analyze)

| วิธีเรียก (Method) | เส้นทางระบุ (Path) | สิ่งที่ต้องป้อนมา (Request) | รูปแบบผลลัพธ์ (Response) | หมายเหตุ / ข้อควรระวัง |
|---|---|---|---|---|
| GET | `/health` | — | คืนค่าดิบ `{status: "ok"}` | ใช้เปิดไว้เผื่อทดสอบเช็คชีพจรว่าเซิร์ฟยังหายใจอยู่ไหม (health check) |
| POST | `/api/analyze` | โยนร่างก้อน `AnalyzeRequest` | **ตีกระจายสตรีม SSE** | ท่านายพลใหญ่ orchestrator คุมคิวหลัก: รับทำคิววงจร Memory→ชี้เป้าRouter→ดันเข้าท่อpipeline |
| POST | `/api/chat` | โยนร่างก้อน `AnalyzeRequest` | **ตีกระจายสตรีม SSE** | ตั้งชื่อแฝง (alias) เลียนแบบทำตัวเหมือนเส้นทางของ `/api/analyze` ทุกประการ |

**เจาะไส้ในของก้อน `AnalyzeRequest`:** ระบุชื่อห้อง `sessionId: str` · ส่งประโยคคำถามมาที่ `prompt: str` · โยนลิสต์ประวัติเก่ามาเผื่อด้วยที่ `history: [{role,text}]?` ·
สั่งลุยในโหมดไหน `mode: str = "normal"` (ตัวเลือกเช่น `normal` โหมดชิวๆ \| `stats` โหมดโหดสถิติ \| `obsidian` โหมดห้องสมุด \| `tavily` โหมดออกเน็ต \| `multi` สั่งผสม \| `research` โหมดวิชาการ \| หรือ `report-gather` โหมดซัดเต็มเหนี่ยวรวบรวมรายงาน) ·
และอาจพ่วงของเล่นมา `tools: str[]`
**กลไกความโหด:** แอบตั้งเพดานขีดจำกัดด้วยยันต์ `BoundedSemaphore(5)`/ต่อเวิร์กเกอร์ — หมายความว่าถ้าคนรุมใช้เกิน 5 สาย มันจะตีหน้ามึนสวนกลับคืนเป็นข้อความ SSE error ปฏิเสธไปว่า "ระบบยุ่ง ขออภัย" ทันที ไม่ยอมปล่อยให้เซิร์ฟแฮงก์ (ตามกติกาใน [[03 - Runtime Views]])

## 2. `accident_chat.py` — โต๊ะกลมคุยเจาะลึกอุบัติเหตุ (prefix `/api/accident-chat`)

| วิธีเรียก (Method) | เส้นทางระบุ (Path) | สิ่งที่ต้องป้อนมา (Request) | รูปแบบผลลัพธ์ (Response) | หมายเหตุ / ข้อควรระวัง |
|---|---|---|---|---|
| POST | `/ask` | ตัวพิมพ์ `AccidentChatRequest` | ตอบมาเป็นร่าง `AccidentChatResponse` | ท่าไม้ตายแบบรุม 2-agent (ตัวนึงดำน้ำหา SQL→ ส่งต่ออีกตัว Answer ช่วยเกลาคำ) |
| POST | `/ask/stream` | ตัวพิมพ์ `AccidentChatRequest` | **ทยอยยิง SSE** | หน้าตาเหมือนท่าแรกแต่แปลงเป็นเวอร์ชันสตรีมให้รออ่านสบายๆ |
| POST | `/quick` | ตัวพิมพ์ `AccidentChatQuickRequest` | คืนค่าเป็นก้อน JSON ดิบๆ | เน้นความไวแสง ดึงผ่าน SQL tools เลย **ไม่พึ่งพลังเวทมนตร์ LLM** เด็ดขาด (เหมาะสำหรับโชว์ตาราง) |
| GET | `/provinces` | — | แค่รายชื่อจังหวัดของเขต 10 | เอาไว้ป้อนดรอปดาวน์ |
| GET | `/districts?province=` | ส่งต้อยติ่งคำว่า `province` ต่อท้าย | ให้รายชื่อลิสต์อำเภอทั้งหมด | |
| GET | `/sample-questions` | — | ชุดตัวอย่างคำถามที่ควรถาม | เอาไว้โชว์ให้ผู้ใช้เห็นว่าระบบเก่งด้านไหน |

**เจาะไส้ในของ `AccidentChatRequest`:** มีประโยคคำถาม `question: str` · ชี้เป้า `province: str` · ชี้เป้า `district: str` ·
ห้วงปี `year_start=2021` · ถึง `year_end=2026` (ระบบบังคับว่าปีนี้ต้องเป็น **ค.ศ.** เท่านั้น)
**เจาะไส้ในของ `AccidentChatQuickRequest`:** ระบุเครื่องมือ `tool: str` · พื้นที่ `province`/`district`/`road_name` · ระบุเจาะจงปี `year=2024` ·
หรือเป็นห้วง `year_start`/`year_end` · ขอเรียง `top_n=10` อันดับ · หรือจะเจาะเป้าหมาย `topic="helmet"` เรื่องหมวกกันน็อค
**ผลประกอบการ `AccidentChatResponse`:** จะพ่นคำตอบมาในซอง `answer` (สวยงามด้วยการตีแผ่เป็น Markdown) · พร้อมซองข้อมูลดิบ `raw_data` · แถมใบเตือนข้อจำกัด `data_limitations[]` · แผ่ลิสต์ท่าที่ใช้ `tools_used[]` · พร้อมใบบิลเวลาที่ผลาญไป `elapsed_seconds` · และเศษเหรียญ `metadata`

## 3. `accident_policy.py` — วงประชุมร่าง Policy Brief เจาะพื้นที่เขต 10 (prefix `/api/accident-policy`)

| วิธีเรียก (Method) | เส้นทางระบุ (Path) | สิ่งที่ต้องป้อนมา (Request) | รูปแบบผลลัพธ์ (Response) | หมายเหตุ / ข้อควรระวัง |
|---|---|---|---|---|
| GET | `/zone10/data` | — | ได้มาเป็น `Zone10DataResponse` | เป็นเส้นทางลัด ดึงตัวเลข SQL ดิบทะลวงตอบมา 7 หมวดคำถาม (**วิ่งโครตไว < 5 วิ**, ไม่ใช้ LLM) |
| POST | `/zone10` | โยนพิมพ์ `AccidentPolicyRequest` | งอกร่าง `AccidentPolicyResponse` | ท่าจัดเต็ม ปล่อย crew ลูกทีม 3 agent ช่วยกันถกเถียงและเรียบเรียงงาน (**กินเวลานาน 2–5 นาที**) |

## 5. `thaijo.py` — สำนักงานสืบค้นหอสมุดงานวิจัย ThaiJo (tags: thaijo)

| วิธีเรียก (Method) | เส้นทางระบุ (Path) | สิ่งที่ต้องป้อนมา (Request) | รูปแบบผลลัพธ์ (Response) | หมายเหตุ / ข้อควรระวัง |

| POST | `/api/thaijo` | ยื่นจดหมาย `ThaiJoRequest` | **ทยอยยิงสตรีม SSE** | ลุยวิ่งผลัด Fetcher→ตามด้วย Planner→ปิดจ๊อบที่ Generator (แถมสตรีมผลงานมาในคราบ HTML) |

| POST | `/api/thaijo/demo` | — | **สตรีมพ่น SSE รัวๆ** | โหมดสาธิตโชว์พาว เดโมด้วยเป้าหมายและข้อมูลจำลองที่เตรียมไว้ |

**ชำแหละคำสั่งชงเรื่อง `ThaiJoGenerateRequest`:** ต้องมีชื่อเรื่อง `query` · เอาก้อนข้อความบทความที่ดึงมาแล้วสาดใส่ `articles_text` · กำหนดทรง `doc_type` · และวางโครงตอนท้าย `topic_plan`

## 8. `db_explorer.py` — ลานสอดส่องส่องกล้อง DB (ดูแต่ตา มือห้ามลบ) (prefix `/api/db`)

| วิธีเรียก (Method) | เส้นทางระบุ (Path) | สิ่งที่ต้องป้อนมา (Request) | รูปแบบผลลัพธ์ (Response) | หมายเหตุ / ข้อควรระวัง |
|---|---|---|---|---|
| GET | `/tables` | — | ลิสต์โชว์รายชื่อตารางทั้งหมด | ให้ผู้คนมองเห็นว่ามีอะไรให้เล่นบ้าง |
| GET | `/tables/{table_name}/columns` | ใส่ชื่อลงช่อง path | แจกแจงย่อยคอลัมน์ | มีระบบตรวจสแกนกันชื่อแปลกๆ (validate ชื่อตาราง) |
| GET | `/tables/{table_name}/rows` | ระบุชื่อ path + เติม query (บอกให้เรียงหน้า paging) | ขุดแถวข้อมูลจริงมาแผ่ | ถ้าเจอแถวตัวเลขเวกเตอร์ยาวย้วย จะสั่งหั่นทิ้งพรางตาก่อน (ตัด vector field ยาว), พร้อมเช็คชื่อกันเละ (validate column) |

> [!warning] โซนนี้เขียนโค้ดล็อกตายให้อ่านได้อย่างเดียว (Read-only) พร้อมวางระบบ validation กันคนพิมพ์ชื่อ table/column ชวนหัวเพื่อสกัดแผนการณ์เจาะระบบ SQL injection แบบเด็ดขาด ตามข้อตกลงที่ให้ไว้ใน ([[05 - Non-Functional Requirements|NFR-SEC-07]])

## 10. `pdf_ingest.py` — โรงงานย่อยกระดาษ PDF & ยัดไส้ Vault (prefix `/pdf`, tags: PDF Ingest)

| วิธีเรียก (Method) | เส้นทางระบุ (Path) | หน้าที่ความรับผิดชอบ |
|---|---|---|
| POST | `/upload` | โยน PDF ข้ามกำแพง (ผ่านท่า multipart แบบก้อนไฟล์ `file`) → เข้าไปนอนรอในถัง MinIO หมวด `pdf-library` |
| POST | `/ingest/{file_id}` | กระตุกสวิตช์เครื่องบดย่อย PDF ให้แตกละเอียดเป็นก้อนเล็กๆ chunk → แล้วอัดเรียงกันสร้างร่างใหม่กลายเป็นหน้า note |
| GET | `/ingest/status/{job_id}` | แวะเข้ามาถามไถ่ว่าเครื่องบดย่อยทำงาน (ingest) ไปถึงไหนแล้ว |
| GET | `/ingest/stream/{job_id}` | แอบดูกระแสสายพาน **SSE** แจ้งความคืบหน้าการย่อยกินสดๆ |
| GET | `/view/{file_id}` | ขอเบิกตัวมาเปิดดู PDF หน่อย |
| GET | `/files` | ขอดูสมุดบัญชีรายชื่อไฟล์ PDF ทั้งหมดในระบบ |
| DELETE | `/files/{file_id:path}` | สั่งปลดระวางลบไฟล์ทิ้งหายไปเลย |
| GET | `/vault/files` | เปิดดูโฉนดรายชื่อไฟล์ที่จัดเรียงอยู่ในโครงสร้างเมือง vault |
| GET | `/vault/folders` | ขอดูรายชื่อโฟลเดอร์ในบ้าน vault หน่อย |
| GET | `/vault/db-stats` | ขอดูสถิตินับจำนวนแผ่น note/หรือก้อนชิ้นส่วน chunk ในตาราง DB ทะเบียนราษฎร์ |
| GET | `/vault/file?path=` | อ่านเปิดส่องดูเนื้อหาไฟล์วิชาการนามสกุล .md |
| PUT | `/vault/file` | ลงมือเขียนหรือแต่งเติมแก้ไฟล์ .md ในฐานข้อมูล |
| DELETE | `/vault/file?path=` | ดึงป้ายลบไฟล์ .md ฉีกทิ้ง |
| POST | `/vault/rename` | ไปอำเภอขอเปลี่ยนชื่อไฟล์ใหม่ (ส่งแนบฟอร์มแบบ body JSON) |
| POST | `/vault/migrate-from-filesystem` | รันคำสั่งอพยพย้ายข้อมูลข้ามภพ จากหน้าดินระบบไฟล์ดิบ filesystem → เข้าสู่อาณาจักร DB |
| GET | `/zone10` | แผ่ข้อมูลสรุปภาพรวมพื้นที่ของเขตที่ 10 ทั้งหมด |
| GET | `/view/obsidian/{asset_id}` | เปิดลิ้งก์งัดดูเอกสาร PDF asset ตามรหัส id โดยเฉพาะ |
| GET | `/view/obsidian/by-note/{note_id:path}` | เปิด PDF ค้นหาดึงขึ้นมาจากรหัสของตัวโน้ตต้นทาง |

> 💡 จุดพักข้อมูล: พวกกอง endpoint ชุมทางกลุ่มนี้ ตัวพนักงานหน้าด่าน frontend จะไม่เรียกตรงๆ แต่จะเดินเข้ามาผ่านช่องทางสาย proxy ชื่อ `/api/pdf/*` เท่านั้น (ไปทบทวนเนื้อหาอ่านเพิ่มเติมได้ที่ [[07 - API Reference — Frontend (BFF)]])

## บทส่งท้าย: ว่าด้วยเรื่องการมัดรวมชุมสายในไฟล์ตัวพ่อ `main.py` (สรุปการ mount ที่ `main.py`)

สุดท้ายนี้ไฟล์แม่ทัพใหญ่ `main.py` จะถูกตั้งค่าให้กดลงทะเบียน (register router) เปิดเส้นทางทีละกระทรวงตามลำดับขั้น: `analyze` · ขยับไป `accident_chat` · ขยับไป `accident_policy` ·
ไล่บี้ที่ `error_log` · ดูแลวิชาการที่ `thaijo` · หาโรคที่ `pubmed` · เปิดคลังช่างที่ `tools_router` · ส่องตำราที่ `obsidian` · ขุดหาความจริงที่ `db_explorer` · ตีแตกข้อมูลที่ `pdf_ingest`
พร้อมกันนี้ก็ได้กันพื้นที่ตั้งเมาท์โฟลเดอร์พ่วง `/static` ทิ้งไว้ (มีถึง 11 หน้า HTML สำหรับเทสระบบเล่นๆ) และยังมีจุดโชว์เดโมหน้าบ้านทางเข้าดัชนีชื่อ `/ui` ติดมาเป็นของแถมด้วย
